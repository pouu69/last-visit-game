# 제작 작업 순서

2026-10-27 사용자가 지정한 **스토리 확정 → 전체 원고 → 경로별 읽기 검토 → 게임 연결 → 화면·AI·연출 → 리허설** 순서로 끝까지 진행한다. 각 단계의 독립적인 일은 에이전트에 병렬 배정하고, 다음 단계는 앞 단계의 통합 결과를 기준으로 시작한다.

- 구현: 아홉 방과 복도, 보행과 충돌, 근접 조사, 실제 조작 퍼즐 3개, 추리 4개, 목적지 도착 상태.
- 이야기 통합: S22 반전 순서 보호, D21 반환실 원본 관찰, P12 시설 운반로와 관람 복도 구분.
- 연출: 비스듬한 일반 시점, 조사 클로즈업, 사용자 확대·회전·시선 높이, 외곽선·문틀·접지 그림자.
- 확인: 핵심 통합 검사 81개 통과. 실제 지도판 11결정→E3 완주, NPC 증거 제시, 데스크톱·모바일 카메라 조작 확인 완료. 사람 리허설은 미실시.

## 공유와 검증 방식

- 각 챕터가 나오는 대로 링크와 일부 대사를 공유하고, 전체 원고 통합본을 기술 구현보다 먼저 보여 준다. 중간 공유는 진행을 멈추는 형식적 승인 절차로 만들지 않는다.
- 원고의 모든 선택에는 선택 전 문장·선택 후 대사/결과·다음 장면이 있어야 한다. 중요한 사실을 API가 즉흥적으로 만들어야만 진행되는 구조로 쓰지 않는다.
- 이미 만든 T22 엔진은 재사용 자료다. 전체 원고를 그 샘플에 억지로 맞추지 않는다. 옛 12단계 engine/story/types는 현재 이야기 기준이 아니다.
- 모든 단계에서 산출물 기준으로 검증한다. 게임 연결과 화면·AI·연출은 실제 브라우저로 확인하고 어색한 흐름을 수정한다. 최종 리허설은 모든 선택/조건부 결과/엔딩을 실행 목록으로 관리한다. 파일별 반복 검사나 동일 검사의 불필요한 확대는 하지 않는다.
- 55분은 목표다. 실제 참가자와의 시간·재미 검증은 사람 리허설이 필요하며 자동 실행으로 대체했다고 주장하지 않는다.
- OpenAI 호출 정보는 사용자가 프로젝트 `.env`에 제공한다. 서버만 읽고, 키 값은 출력·브라우저 전송하지 않는다. 원격 배포에 필요한 계정/권한은 구현과 구분해서 보고한다. 무단 푸시·외부 배포하지 않는다.
