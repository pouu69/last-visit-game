# 행동으로 시작하는 마지막 관람

새 플레이어는 로비에서 자신이 초대받은 관람객임을 알고, 직접 걸어 첫 사건을 발견한다. 읽기 전용 프롤로그의 페이지 수를 늘리는 것으로는 방문 이유·조작·조사 목적이 연결되지 않는 문제를 해결할 수 없다.

## 검토 결과와 선택

기존 도입은 게임 세션 밖의 다섯 페이지였다. 본편은 전시실의 대화에서 시작했고, 윤서의 부탁과 다음 날 일정을 읽지 않아도 경로를 선택할 수 있었다. 필수 추리는 보조 버튼 안에 숨어 있었고, 완료한 조사와 중단한 조사도 같은 복귀 문구를 사용했다. 공간에서는 이동을 시작할 때 배우가 도착 방으로 즉시 재배치됐다.

사용자가 요청한 계획 수립과 병렬 실행 범위에서 **O00 도입 장면 하나와 공통 행동 안내**를 추가한다. 기존 공간·조사·이동 상태머신을 재사용한다. 영상/페이지를 추가하는 대안은 실제 조작을 익힐 수 없고, 별도 튜토리얼 엔진은 저장과 진행 규칙을 이중화하므로 채택하지 않는다. 새 의존성은 없다.

## 플레이 계약

| 순서      | 플레이어가 하는 일                          | 이때 알게 되는 것                                     | 다음 행동            |
| --------- | ------------------------------------------- | ----------------------------------------------------- | -------------------- |
| 로비      | 안내대까지 걷는다                           | 마지막 관람에 초대받은 손님이라는 역할                | 초대장 확인          |
| 초대장    | 접근해 조사하고 끝까지 읽는다               | 마지막 관람일, 윤서를 찾아야 하는 이유, 안내지의 빈칸 | 윤서 만나기          |
| 윤서      | 가까이 가서 인사를 나눈다                   | 관장과 안내 로봇 소개, 첫 전시품 관람 목적            | 북쪽 문으로 이동     |
| 전시실    | 복도를 직접 걸어 도착한다                   | 장소와 이야기의 연결                                  | 제1호 진열장 조사    |
| 실종      | 진열장을 살핀다                             | 종이배가 없어졌지만 유리는 깨지지 않음                | 모로와 물자국 확인   |
| 부탁·기한 | 모로의 등장과 윤서의 부탁, 일정표를 읽는다  | 배를 찾는 이유, 내일 9시와 사흘 뒤 개봉의 충돌        | 관찰과 추측 구분     |
| 첫 결정   | 확인한 사실을 대조하고 A–D 중 경로를 정한다 | 무엇을 더 알아내려 어떤 방으로 가는지                 | 선택한 장소까지 이동 |

O00의 본문은 [실행 원고](../../src/content/opening.mjs)에 한 번만 둔다. 도입은 자원·주요 결정·엔딩을 바꾸지 않는다. 새 게임은 `museum-map-4`, 이전 `museum-map-3`은 S01 시작과 종전 조사 규칙을 보존한다. 기존 주요 결정은 한 경로당 11회다.

## 입력과 실패의 범위

- `INSPECT invitation`을 끝내야 `curator`가 공개된다. 읽기 중 `EXPLORE`로 나오면 기록하지 않으며 같은 조사부터 다시 읽는다.
- 두 관찰을 끝내야 `CONTINUE`가 가능하다. 전시실 이동 동안 미공개 S01 단서·대사는 보이지 않는다. 올바른 방의 `ARRIVE`만 장면을 연다.
- map4 S01은 `case → trail → schedule` 순서로 열리고 세 관찰과 추리가 끝나야 경로를 고른다. 원문의 사건·반전은 유지한다.
- 도입 자유 AI 질문은 없다. 모로는 로비에 나타나지 않는다. 본편의 텍스트 NPC 대화·추궁은 기존 경계에서 제공한다.
- 새 게임은 곧바로 서버 세션을 만든다. 중간 이탈·재접속은 현재 메시지와 관찰을 복원한다. 읽는 시간에 벌점이 없다.
- 도입 건너뛰기는 재플레이용 보조 행동이다. O00/첫 전시실 이동에서만 허용하고 S01 조사·추리를 완료한 것으로 처리하지 않는다.
- 오래된 revision, 잠긴 조사, 잘못된 도착, 미완료 계속하기는 상태를 보존하고 명시적으로 거절한다. 요청 대기 중 중복 입력을 막고 네트워크 실패는 재시도할 수 있다.

## 본편 전체에 적용할 안내

서버가 `exploration.objective`, `reason`, `recommendedHotspotId`, `primaryAction`을 계산한다. UI는 **필수 조사 → 추리/퍼즐 → 선택/이동** 중 지금 가능한 다음 행동을 주 버튼으로 표시한다. 3D는 같은 추천 대상을 하나의 표식으로 보여 주고 접근·카메라만 담당한다. 서버 승인 없이 원거리 조사나 이야기 전이를 하지 않는다.

역할과 장의 질문은 화면에 남긴다. 1장은 사라진 배의 행방, 2장은 반환을 둘러싼 설명과 약속, 3장은 구조한 물건·기록과 실제 인계로 이어진다. 아직 드러나지 않은 반전은 목표 문구로 선공개하지 않는다. 결과를 읽은 뒤에는 다음 장면 코드 대신 장소와 이동 목적을 안내한다.

첫 선택 A–D의 결과는 map4에서 출발 결심 한 문장으로 보여 준다. 원래 결과 대사는 버리지 않고 목적지 도착 후 새 장면 도입 앞에 둔다. 이동 중에는 대사와 단서를 공개하지 않는다. 따라서 기록실 문을 열고 표제를 발견하는 서술이 실제 기록실 도착보다 앞서지 않는다.

## 병렬 소유와 검증

- 엔진 담당: 버전·O00·순차 조사·저장 재생·공통 행동 메타데이터·핵심 통합 테스트.
- UI 담당: 새 게임 진입·목표와 주 행동·중단/완료 피드백·지도/모바일 안내.
- 공간 담당: 초대장·로비 윤서·조사/이동 표식·배우 이동과 카메라 소유.
- 통합 담당: 도입 원고·문서·실제 브라우저 플레이와 최종 연결 확인.

실제 입력으로 로비부터 첫 경로 도착까지 플레이하고, 도중 저장 재개·기존 저장 재생·모바일 목표/버튼을 확인한다. 엔진의 중요한 거부·진행 사례는 기존 통합 검사에 묶고, 별도 파일 단위 테스트를 늘리지 않는다. 빌드·정적 검사와 실제 화면 근거를 함께 기록한다.
