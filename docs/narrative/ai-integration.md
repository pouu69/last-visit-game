# NPC AI 연결

> 과거 설계 기록입니다. 현재 버전은 AI 연결을 제거한 정적 게임이며 이 문서의 API·환경변수·서버 설정을 사용하지 않습니다. 현재 실행과 저장 방법은 [README](../../README.md)를 따릅니다.

자유 질문은 실제 OpenAI API로 해석하고 답하되, 서명·소지품·이동·엔딩은 게임 상태머신만 변경한다. GPT-Live와 음성 기능은 사용하지 않는다.

## 서버 계약

`npcConfigFromEnv(env)`는 `OPENAI_GPT_MODEL`, `OPENAI_API_KEY`, `OPENAI_GATEWAY_BASE_URL`을 `{model, apiKey, baseUrl}`로 읽는다. 누락·잘못된 URL·잘못된 모델 이름 형식에는 값이나 URL을 포함하지 않는 `TypeError`를 던진다. 서버는 설정 오류를 잡아 고정 대사로 게임을 계속 제공할 수 있다. 설정과 키는 브라우저에 보내지 않는다. Responses는 설정 모델을 그대로 사용하고 Decisions는 공식 지원 모델 `gpt-6-luna`를 사용한다. 현재 설정 모델도 `gpt-6-luna`다.

`createNpcRunner(config, {fetchImpl=fetch}={})`가 반환하는 함수는 `await run(effect, {signal})`로 호출한다. 입력은 엔진의 `AI_REQUEST`이며, 성공은 `{ok:true,result:{interpretation,replies}}`, 실패는 `{ok:false,reason}`이다. 실패 사유는 `timeout`, `refusal`, `invalid_output`, `quota`, `network` 중 하나다. 취소한 요청의 결과는 서버가 버리며 취소를 실패 대사로 재반영하지 않는다.

## 한 턴의 흐름

1. T22는 한 Decisions 요청의 `choice` 질문 세 개로 의도, 수신 부인 반박의 성립 여부, 발화가 실제로 사용한 근거를 분리해 판정한다. 문서를 보유한 것과 그 문서를 추궁 근거로 사용한 것을 구분한다. 엔진이 지원하는 유한한 해석 값으로만 변환한다.
2. 모호한 질문, 근거 없는 추궁, 행동 요청은 생성문 없이 엔진의 고정 반응으로 끝낸다. 이는 정상적인 판정 결과이며 API 장애 대체와 구분한다.
3. 허용된 질문은 Responses에서 NPC의 새 문장 2~4개를 생성한다. 이미 공개된 메시지, 실제 소지 자료, 알려진 사실, 이번 규칙으로 허용된 핵심 응답만 전달한다. 원고 전체나 미래 장면은 전달하지 않는다.
4. 생성문은 사용한 근거 ID를 반환해야 한다. 서버가 ID와 출력 형식을 검사하고, Decisions가 전체 응답의 근거 일치·모순·임의 실행 여부를 추가 검증한다. 검증을 통과하지 못하면 `invalid_output`으로 돌려 고정 대사를 사용한다.
5. T22의 핵심 인정문은 기존 상태머신의 작성 대사로 먼저 공개한다. AI 표현이 이 사실을 대체하거나 직접 새 사실 플래그를 추가하지 않는다.

T22는 최대 3회, T21·S31은 최대 2회 호출한다. 자동 재시도는 없으며 한 턴은 총 15초, 생성 출력은 700토큰, API 응답은 128KB까지다. 질문은 600자, 생성 메시지는 최대 3개·각 600자다. 문맥은 현재 장면에서 공개된 메시지 중 최대 48개·24,000 UTF-16 문자와 실제 보유 자료·확인 사실로 한정한다. 장면당 3턴 상한과 늦은 응답 거부는 엔진·서버가 담당한다. 모델이 반환한 신뢰도는 성공 임계값으로 임의 사용하지 않는다. 판정 범주에 `unclear`를 명시하고 확률 보정을 했다고 주장하지 않는다.

## 한계와 검증

근거 ID와 추가 모델 검증은 대사 모순을 줄이는 방어이며 완벽한 환각 방지를 보증하지 않는다. 자원·경로 상태는 생성문과 분리되어 있으므로 모델이 잘못 말해도 자동 실행되지 않는다. 실패 시 AI 응답을 성공한 것처럼 표시하거나 다른 API로 조용히 바꾸지 않는다.

2026-10-27 현재 `.env`의 모델·게이트웨이로 아래 사례를 실제 호출했다. 모든 기록된 API 응답은 HTTP 200이었다. 시간은 해당 호출 1회의 관측값이며 성능 보장이 아니다. 키와 게이트웨이 주소는 기록하지 않는다.

### AI-1 — 문서 소유와 발화 근거의 혼동

첫 실사용 검증에서 요청서를 선택하고 “열쇠가 닳았으니 어제 반환실을 열고 요청을 받았다는 증거 아닌가요?”라고 물었을 때, 모델이 요청서의 사실을 질문의 근거로 섞어 `supported`를 반환했다. `stated_basis` 질문을 별도로 두고 질문 자체의 근거가 `receipt_confirmation`인 경우에만 수신 추궁 성공 후보로 전달하도록 보완했다. 열쇠·단정·모호한 근거는 성공으로 변환하지 않는다. 이 입력은 통합 회귀 검증에 포함한다.

## 공식 근거

- [Decisions API](https://developers.openai.com/api/docs/guides/decisions): `/v1/decisions`, 현재 지원 모델 `gpt-6-luna`, `choice`·`predicate`·`score`와 refusal.
- [Responses 텍스트 생성](https://developers.openai.com/api/docs/guides/text): `output` 전체의 메시지 콘텐츠에서 텍스트 추출.
- [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs): `text.format`의 엄격한 JSON Schema와 refusal 처리.
- [gpt-6-luna](https://developers.openai.com/api/docs/models/gpt-6-luna): Responses, Structured Outputs, reasoning effort 지원.
