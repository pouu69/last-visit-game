# 설계 검증과 남은 작업

전체 이야기·분기는 검토용 초안이며, 별도로 승인된 T22 상태머신은 구현했다. 웹 게임 완성본이나 사람 플레이테스트 결과는 아니다.

## T22 구현 검증

- `node --test tests/game-state.test.mjs`: 42개 사례 통과. 정상 추궁·서명/장비 선택, 선행 인정 유지, 자료 미보유, 잘못된 판정, 취소·중복·늦은 응답·팀 분리·사건 재생을 검사했다.
- `node scripts/demo-t22.mjs`: 31개 메시지의 예제 진행과 D21 인계를 실행했다. 같은 확정 사건을 재생한 상태와 메시지가 일치했다. 결과는 `artifacts/t22-demo.md`에 있다.
- TypeScript 5.8.3의 `--allowJs --checkJs --noEmit --target es2023 --module nodenext`로 새 소스 두 파일의 검사 통과. 같은 설치의 Language Service 포매터를 새 소스·테스트·데모 파일에 적용했다.
- ESLint 8.43.0으로 새 파일 네 개의 미정의/미사용 변수, 도달 불가능 코드, typeof, 중복 키를 검사해 경고·오류 없이 통과했다. 기존 로컬 설치를 사용했으며 프로젝트 의존성은 추가하지 않았다.
- 잘못된 JSON 사건 type에 의한 예외와, 부인 전 요청서 질문에 존재하지 않는 부인을 인용하던 문제는 실패하는 사례를 먼저 확인한 뒤 수정했다.
- 실제 API 호출·모델 의미 판정·브라우저·음성·Three.js는 검증 대상이 아니었다. 웹 빌드 설정은 아직 없으므로 배포 빌드는 수행하지 않았다.
- 사용자 요청에 따라 추가 검증 확대를 중단했다. 이후 변경은 실제 진행을 깨뜨릴 수 있는 핵심 시나리오 중심으로 확인한다.

## 실행한 구조 검사

재현 명령: `python3 scripts/check-narrative.py`

- 선택 장면 21개, A~D 선택 84개, 조건부 목적지를 나누면 연결 89개.
- 모든 경로는 정확히 11번 결정한 뒤 종료한다. 순환·없는 목적지·도달 불가능 장면을 발견하지 않았다.
- 엔딩 판정에 영향을 주는 상태와 미션2 실패 여부를 기준으로 12,480개 상태 키와 24,868개 전이를 검사했다.
- 여섯 엔딩이 모두 도달 가능하며, 미션2 오답을 경험한 경로에서도 각각 도달 가능하다.
- 미션1 기록 경로는 A, 현장 경로는 B, 미션2는 B가 유일한 정답이다. 순열과 경로 비용을 별도로 비교했다.
- 훼손된 원본의 부활, 밀봉된 배의 순간 이동, 배터리 소비 없는 모로의 당일 재가동을 거부하는 조건을 확인했다.
- 원본 장부 하나만으로 기관의 변경 사실을 증명하지 않도록 검사했다. 작동하는 모로의 추가 로그와 남은 배터리가 실제 판정에 영향을 주는 것도 확인했다.

전체 결과는 `artifacts/narrative-check.json`에 있다. 검사 모델은 문서의 규칙을 별도로 옮긴 검토 도구다. 문학적 인과관계·원고 품질·화면 동작까지 증명하지 않는다. 아직 게임 엔진에 이 설계를 구현하지 않았다.

## 서로 다른 세 팀의 예시

| 경로 | 주요 결정 | 결과 |
| --- | --- | --- |
| 배를 돌려보낸 팀 | 전원·도면·배수 준비를 모으고 정상 인양 뒤 외부 구조 사용 | E1. 배와 원본이 온전하고 모로도 작동한다. 비상 배터리는 소모했다. |
| 규약 변경을 밝혀낸 팀 | 기록과 보수 도구를 확보했지만 미션2 실패. 원본부터 구조하고 남은 배터리로 모로를 깨워 로그 추출 | E3. 공식 시정 근거를 확보했다. 배는 손상 상태로 남는다. |
| 모로를 데리고 나온 팀 | 장비를 준비했지만 미션2 실패. 배터리와 모로의 전원으로 둘을 구조한 뒤 안내원을 직접 이동 | E5. 배와 원본은 온전하다. 모로는 잠든 상태로 안전하게 옮겨진다. |

이 표는 가능한 예시이며 실제 세 팀의 결과를 강제하지 않는다. 같은 엔딩이 나와도 조사 경로와 구조 결과를 비교할 수 있다.

## 독립 검토에서 발견하고 반영한 사항

| 지적 | 문서 반영 |
| --- | --- |
| 앞서 얻은 동의를 마지막에 자동 보충해 초반 선택이 무효가 됨 | 기본 동의는 공통 확인 절차로 옮겼다. 해당 조사 선택은 수신 확인이 찍힌 반환 요청서를 확보하며, 실제 증거 조합에 사용한다. |
| 퍼즐에서 이미 인양·전원 해제를 하고 다음 장면에서 또 인양함 | P21은 실행 전 제어 예약 검증이다. 실제 대상 선택과 실행은 R31/R32가 담당한다. |
| 모로를 재우는 대가가 작아 다른 구조 선택을 압도함 | 방전하면 아직 저장하지 않은 로그를 추출할 수 없다. 마지막 정정 방송의 실행 방법과 결과에 영향을 준다. 남은 배터리는 실제로 소모해 깨울 수 있다. |
| 안전 밀봉에 지연 비용이 없어 지금 구조할 이유가 약함 | 내일 아침 배 띄우는 날과 사흘 뒤 전문가 개봉 일정을 도입에서 함께 알린다. 밀봉은 안전하지만 원래 배가 내일 모임에 참여하지 못한다. |
| S12에서 보지 않은 열쇠·기록을 증거로 제시함 | 합류에서 누구나 열쇠를 보며, 선택은 그 열쇠의 사용 여부를 묻는 것으로 바꿨다. |
| 규약 자료로 나래의 개인 사연까지 입증하려 함 | 증거 조건은 기관의 반환 규약 변경 사실에만 적용한다. 당사자가 직접 확인한 자신의 사연을 부정하지 않는다. |
| 마지막 장이 운영 회의로 흘러 미스터리·모험과 어긋남 | F33은 모로 이동, F34는 마지막 현장 인계 장면으로 바꾸고 운영 방침 회의는 후속 비교 시간으로 넘겼다. |

독립 검토 1회 후 수정하고 구조 검사를 다시 실행했다. 수정본 전체에 대한 추가 독립 검토나 사람 플레이테스트를 완료했다고 주장하지 않는다.

## NPC 추궁 콘티의 문서 대조

- I04에서 이미 요청 수신을 인정한 윤서가 T22에서 다시 부정하지 않도록 입장 조건을 구분했다. 요청서를 챙기지 않은 I04-C/D에도 선행 인정은 유지한다.
- 열쇠 마모로 최근 사용을 확정하던 S01-D의 설명을 관찰 가능한 사실로 수정했다. 최근 사용 여부와 요청 수신 여부는 별도로 확인한다.
- T22-A의 서명에는 공식 시정 증거로 필요한 규약 변경 사실이 포함되도록 원문 대조 과정을 명시했다. 구두 수신 인정만으로 서명 증거를 얻지 않는다.
- 구조 검사 재실행 결과는 위와 동일하다. [T22 콘티](t22-storyboard.md)의 사례 표는 아직 실행하지 않은 대화 평가 기준이며, 구조 검사의 통과 범위에 포함되지 않는다.

## 아직 검증하지 않은 것

- 이 사건과 반전이 사용자가 원하는 재미인지: 사용자 방향 검토가 필요하다.
- 장면 원고의 몰입감: 현재는 장면 설계와 선택 명세이며 완성 원고가 아니다.
- 55분 분량: 목표일 뿐 미실측이다. 특히 퍼즐은 기본 관찰·순서 추리 수준이어서 실제 풀이 시간을 확인해야 한다.
- 선택 토론의 질: 3~4명 종이 플레이로 압도적으로 많이 선택되는 답, 지루한 반복, 설명이 필요한 규칙을 기록한다.
- 엔딩 후일담의 모든 문장 조합: 원고 작성 후 배·원본·모로·최종 행동의 조합별 모순을 점검한다.
- 웹 화면·저장·복원·Three.js·접근성·성능: 구현 전이므로 빌드·브라우저 테스트 결과가 없다.
