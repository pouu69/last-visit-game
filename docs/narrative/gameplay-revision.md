# 플레이 방식 수정 제안

> 초기 조사판 구현 계획의 이력이다. 이후 AI와 게임 서버를 제거했으며 현재 실행·저장 계약은 [전체 게임 연결 계약](runtime-contract.md)을 따른다.
> 이전 결과는 원고와 분기를 재생하는 이야기 뷰어에 가까웠다. 사용자가 원한 게임으로 완료되었다는 이전 판단을 철회한다. 사용자의 “전부 다 수정해” 지시로 장면 클릭 조사형을 기준으로 전체 수정에 착수했다.

## 구현 계약

- 후속 요청으로 연결된 큰 맵과 직접 보행을 추가했다. 새 게임은 지도형 `museum-map-3`로 시작하며 `museum-play-2` 조사판과 `museum-full-1` 읽기판은 기존 진행 규칙으로 보존한다. 현재 기준은 [지도 게임 계약](map-gameplay.md)이다.
- `INSPECT`는 현재 장소의 물체만 조사한다. 해당 대사 블록의 마지막 메시지를 읽었을 때 관찰이 기록된다. `EXPLORE`로 중단할 수 있으며 완료하지 않은 조사는 다시 볼 수 있다.
- `DEDUCE`는 관찰을 바탕으로 해석한다. 오답은 구체적인 피드백을 주고 다시 시도한다. `SOLVE`는 완성한 퍼즐을 제출하며, 서버가 배열을 검증해 경로를 확정한다.
- 필수 관찰·추리 전에 주요 선택을 제출하면 거절한다. 중복 조사, 잘못된 조각·장소, 낡은 revision은 자원이나 경로를 바꾸지 않는다. AI 요청 중에는 조사 입력을 막고 취소 후 돌아간다. 종료 뒤에는 새 행동을 받지 않는다.
- 21개 장면의 전체 본문을 물체별 블록으로 나눈다. 일부 읽기 순서는 플레이어가 정하되, 요청 수신 인정·나래의 뜻·구조 조건처럼 결정에 필요한 대사는 해당 장면에서 확인한다.
- 도장과 인양은 24개 자유 배열을 평가한다. 기존 네 대표 답의 결과는 유지하고, 추가 배열은 실패한 규칙에 따라 결정론적으로 분류한다. 화면에는 제출한 배열의 실제 오류를 설명하며 다른 배열의 원고를 대신 보여 주지 않는다.
- 새 라이브러리 없이 기존 서버·상태머신·Three.js를 사용한다. 공개 화면에는 아직 조사하지 않은 본문이나 추리 정답을 보내지 않는다.

## 문제와 방향

현재 공간은 대사에 반응하는 배경이다. 유리 상태, 물자국, 일정표는 다음 메시지를 누르면 공개되고, 퍼즐도 완성된 순서 중 하나를 선택한다. 플레이어가 조사 대상을 고르고, 단서를 사용하고, 가설을 시험하는 과정이 비어 있다. 그래픽과 대사량만 바꿔서는 해결되지 않는다.

제안하는 장르는 **장면을 직접 조사하는 협동 미스터리 어드벤처**다. 팀은 현장을 조사하고, 발견한 근거로 인물의 말을 검토하고, 장치를 이해한 뒤 중요한 행동을 합의한다. 긴 대사는 유지하되 조사·추궁·사건 발생에 따라 나눠서 만난다.

## 반복할 플레이

**현장 조사 → 단서 대조·NPC 추궁 → 장치 해결 → 팀 결정 → 공간과 관계의 변화.**

| 행동 | 플레이어가 하는 일                                                 | 결과와 피드백                                                                                            |
| ---- | ------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------- |
| 조사 | 진열장의 명패와 걸쇠, 모로의 집게, 안내문 등 관심 대상을 고른다.   | 관찰한 부분이 확대되고 확인한 사실만 기록된다. 아직 보지 않은 내용을 대사가 대신 확정하지 않는다.        |
| 추리 | 관찰과 진술을 나란히 보고 무엇을 뒷받침하거나 반박하는지 판단한다. | 사실과 추측을 구분한다. 틀린 가설은 근거가 부족한 부분을 알려 주며 수정할 수 있다.                       |
| 추궁 | 보유한 문서를 선택하고 그 문서의 내용으로 NPC에게 질문한다.        | NPC가 제시한 근거에 반응한다. AI가 발견하지 않은 단서를 주거나 루트·자원을 바꾸지는 않는다.              |
| 퍼즐 | 운송표의 도장이나 인양 제어기의 순서를 직접 놓고 비교한다.         | 배열·검증·확정을 구분한다. 실패하면 어떤 규칙과 충돌했는지 알 수 있고, 원고의 수동 복구 경로로 이어진다. |
| 결정 | 장비 사용과 구할 대상을 팀이 합의해 확정한다.                      | 소지품, 장치, 인물 상태와 이후 경로가 함께 바뀐다. 결과 설명만 바뀌는 선택을 피한다.                     |

실시간 제한이나 반사신경 벌점은 두지 않는다. 긴장은 서로 다른 근거, 한정된 장비, 무엇을 먼저 구할지의 선택에서 만든다. 조사 중 재시도와 주요 선택 확정 뒤의 결과는 구분한다.

## 먼저 보여 줄 플레이 구간

목표는 첫 전시실부터 첫 퍼즐 결과까지 약 5~10분의 플레이다. 시간은 미측정 목표다. 첫 방에 클릭 지점만 추가한 상태를 완료로 보지 않는다.

1. **S01 빈 진열장:** 짧은 도입 후 조사를 시작한다. 진열장, 모로의 젖은 종이, 일정표를 원하는 순서로 살펴본다. 모든 물체를 클릭해야 통과하는 수집 과제로 만들지 않는다.
2. **조사 방향 결정:** 모로·기록실·안뜰·윤서가 각각 기존 A–D 경로의 대상이 된다. 조사 내용과 미확인 사항을 보고 다음 장소를 결정한다.
3. **I01 정비 통로:** 첫 대표 경로에서는 모로의 단말과 정비함을 살펴보고 어떤 자료 또는 장비를 챙길지 고른다. 접수표라는 사실은 이 장소에서 공개한다.
4. **P11 네 개의 도장:** 도장 배치판에서 규칙을 적용해 보고 제출한다. 성공 시 자료함이 열려 도면을 얻고, 실패 시 충돌한 규칙을 확인한 뒤 수동 통로로 진행한다. 자유 배치와 기존 네 선택의 대응은 구현 전에 명세로 확정하며 임의로 같은 결과에 뭉개지 않는다.
5. **되돌아보기:** 팀이 무엇을 직접 발견했는지, 어디에서 판단했는지, 그 판단이 이후 플레이에 무엇을 남겼는지 확인한다.

첫 구간에서 조사의 이유와 퍼즐의 재미가 드러난 뒤 다른 경로와 챕터에 확대한다. 이후 2장은 증거를 사용하는 추궁, 3장은 장비와 대상의 구조 결정을 중심으로 구성한다.

## 조작 방식의 대안

- **장면 클릭 조사형 — 추천:** 공간의 물체와 출입구를 클릭·터치한다. 카메라가 조사 대상으로 다가가고, 키보드로도 같은 대상을 고른다. 한 기기를 보며 토론하는 팀 플레이에 맞고 기존 장면을 활용할 수 있다.
- **캐릭터 직접 이동형:** 방향키 또는 이동 지점을 눌러 인물을 움직이고 가까이에서 조사한다. 공간 탐험은 강해지지만 이동·충돌·길찾기·모바일 조작까지 설계가 필요하다.

## 유지할 기반과 영향

- 사건의 진실, 인물의 동기, 세 챕터와 엔딩은 유지한다. 원고의 조사·추리 대사를 실제 행동에 맞게 재배치한다.
- 주요 분기 A–D와 팀 합의는 유지한다. 조사·배치 같은 세부 입력을 매번 새 이야기 분기로 늘리지 않는다.
- 현재 서버 상태머신, 경로 규칙, 저장 검증, Responses·Decisions를 재사용한다. 새 관찰·퍼즐 상태의 저장 호환성은 별도로 정의한다. 기존 기록을 조용히 덮어쓰지 않는다.
- 새로운 라이브러리, 외부 배포, 그래픽 자산 교체를 이 제안의 전제로 삼지 않는다.

## 완료를 판단할 기준

- 플레이어가 대사 진행 외에 발견·근거 사용·퍼즐 조작을 실제로 수행한다.
- 잘못된 판단이 어떤 근거와 어긋났는지 알 수 있고, 게임이 멈추지 않는다.
- 얻은 자료나 쓴 장비가 다음 상황에서 작동한다.
- 첫 플레이 구간을 화면으로 공유하고 피드백을 반영한다. 자동 검사는 상태·저장·분기 등 핵심 회귀만 묶어서 확인한다.
- 기존 기술 리허설 결과를 재미나 게임성의 증거로 제시하지 않는다.
