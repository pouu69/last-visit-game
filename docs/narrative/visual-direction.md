# 연결된 박물관 공간과 연출

플레이어는 하나로 이어진 박물관을 걸어서 조사한다. 이야기가 다음 방으로 넘어가면 목적지까지 직접 이동하고, 그 방에 도착한 뒤 다음 대사가 열린다. 발견·추리·자원 획득·분기 판정은 서버 상태머신이 담당한다.

## 공간과 이동

공간의 기준은 `public/museum-map.mjs`다. 서버의 도착 판정, Three.js 바닥과 문, 충돌, UI 미니맵이 같은 방·복도 데이터를 사용한다. 각 방은 12×10 단위이며 3.6 단위 너비의 복도가 이어진다. 문은 복도와 같은 중앙 위치에 둔다.

| 북쪽                             | 중앙                         | 남쪽                           |
| -------------------------------- | ---------------------------- | ------------------------------ |
| 정비 통로 · 반환실 · 인양 제어실 | 기록실 · 제1 전시실 · 관장실 | 안뜰 · 중앙 로비 · 반환 접수실 |

WASD와 방향키로 이동하고 바닥을 클릭하거나 터치하면 그 위치까지 걷는다. 클릭 이동은 0.5 단위 격자의 제한된 너비 우선 탐색으로 문을 통과하는 경로를 찾는다. 플레이어의 반지름을 포함해 방과 복도 경계를 검사하고, 진열장·기록 책상·관장실 책상·반환실 보관함·접수 카운터의 단순 충돌 영역도 검사한다. 프레임 간 이동량을 제한하고 작은 구간으로 나누어 벽을 건너뛰지 않도록 한다. 별도 물리 라이브러리는 사용하지 않는다.

플레이어는 주황색 겉옷, 배낭, 짧은 다리로 윤서와 구별한다. 이동 방향을 바라보고 걸을 때만 다리를 움직인다. 카메라는 약 43도의 비스듬한 사선 구도로 방의 앞면과 옆면을 함께 보여 주며 플레이어를 따라간다. 키보드 방향은 이 카메라의 화면 방향을 지면에 투영해 적용한다. 탐색에서는 플레이어를 화면 중앙에 놓고 상하 시야를 대칭으로 확보해 북쪽과 남쪽 출입구를 함께 읽을 수 있게 한다. 목적지 방에는 녹색 고리와 화살표가 나타난다. 미니맵은 현재 방·플레이어 위치·목적지를 UI에서 표시한다.

처음 시작하거나 저장 상태를 불러올 때만 현재 방의 시작 위치에 놓는다. 같은 방에서 대사가 바뀔 때 위치를 유지하며, 다른 방으로 향하는 `travelling` 단계에서도 순간이동하지 않는다. 목적지 경계에 도착하면 `onArrive(roomId)`를 한 번 보내고 서버의 도착 승인을 기다린다.

## 조사와 UI 계약

`mountMuseum(element, { onInspect, onArrive, onNavigation, onCameraChange })`는 조사·도착·위치·카메라 변경 콜백을 받는다. `update()`에는 공개된 `sceneId`, `flags`, `phase`, `speaker`, `messageId`, `hotspots`, `activeHotspot`, `interactive`와 `mode`, `currentRoomId`, `travel`을 전달한다. `onNavigation`은 좌표·현재 방·목적지·이동 여부·가까운 조사 대상 이름이 바뀔 때 최대 초당 10회 전달한다.

`playthroughId`는 브라우저의 플레이 시작·복원 세대를 나타낸다. 이 값이 바뀌면 마지막 도착 방에 캐릭터를 배치하고 보행 입력을 비운다. 같은 플레이 안의 방 도착은 좌표를 초기화하지 않아 문을 통과한 위치를 유지한다.

물체 또는 UI의 조사 버튼은 `approach(hotspotId)`를 호출한다. 가까우면 조사 사건을 보내고, 멀면 물체 주변의 걸을 수 있는 위치로 이동한 뒤 조사한다. E키는 2 단위 이내의 가장 가까운 공개 조사 대상을 연다. 도달할 수 없는 대상은 `false`를 반환하고 UI가 안내한다. 카메라만 조정하는 `focus(anchor)`는 게임 상태를 바꾸지 않는다.

관찰 대사의 마지막 메시지를 읽은 뒤 서버가 대상을 확인한 것으로 표시한다. 시각 모듈이 클릭 자체로 자료나 배터리를 지급하지 않는다. 물체에 가까이 가는 과정과 단서를 읽는 과정은 구분된다.

가로 폭 700px 이상에서는 물체 위치에 이름 있는 HTML 버튼을 투영한다. 클릭·터치·Tab/Enter 모두 접근 동작을 사용한다. 포인터나 초점이 올라오면 물체에 얇은 테두리를 표시한다. 좁은 화면에서는 UI의 조사 목록으로 접근한다. 큰 화면에서도 같은 목록이 남는다.

`interactive: false`에서는 탐색과 이동을 모두 멈춘다. 요청 처리 중, 대사, 퍼즐, 확대 지도와 다른 패널에서도 UI가 이 값을 통제한다. 입력·텍스트 영역·선택 상자·버튼·summary·편집 가능한 요소에 초점이 있거나 모달이 열리면 이동 키를 처리하지 않는다. 캔버스를 클릭하거나 탐색으로 돌아오면 캔버스에 초점을 둔다.

## 사용자가 조절하는 카메라

캔버스의 휠로 확대·축소하고, 마우스 오른쪽 버튼 또는 Shift를 누른 채 드래그하면 시야를 회전하고 높인다. 터치에서는 두 손가락의 간격으로 확대하고 두 손가락을 가로로 움직여 회전한다. 한 손가락의 짧은 탭만 바닥 이동으로 처리하며 드래그와 두 손가락 동작 뒤에는 이동을 만들지 않는다. 입력 요소에 초점이 있거나 모달이 열리면 캔버스 카메라 조작을 처리하지 않는다.

UI 버튼은 `adjustCamera({ zoomFactor, yawDelta, pitchDelta })`를 호출한다. 확대 인자는 현재 수동 배율에 곱하며 각도 변화량은 도 단위다. 수동 배율은 0.6~1.8, 내려다보는 각도는 25~70도로 제한한다. 수동 배율은 조사 시 자동 확대와 합성하되 최종 배율은 4를 넘지 않는다. 사용자 조절값은 조사와 탐색 사이에 유지된다. `resetCamera()`는 수동 배율 1, 회전 35도, 내려다보는 각도 43도로 복원한다.

`onCameraChange({ zoom, pitch, yaw })`의 zoom은 수동 배율이며 나머지는 도 단위다. 실제 자동 확대까지 합성한 배율은 `diagnostics().cameraZoom`으로 확인한다. 수동 드래그는 즉시 따라가고, 새 조사 대상을 선택하면 기존 자동 전환을 적용한다. 카메라가 돌아가는 중에도 실제 화면 방향을 기준으로 WASD 이동을 계산한다.

## 방별 조형

- 제1 전시실: 비어 있는 유리 진열장, 로프, 아치창, 젖은 바퀴 자국과 일정판. 구조한 배를 이 진열장에 다시 넣지 않는다.
- 정비 통로: 어두운 바닥, 황동 배관, 낮은 작업함과 비상 장비.
- 기록실: 서가, 독서등, 접수 기록, 겹쳐 붙인 표제와 도장 작업대. P11 도장 퍼즐을 여기에서 연다.
- 관장실: 목재 바닥, 붉은 깔개, 책상 위 열쇠 꾸러미와 윤서.
- 안뜰: 돌무늬 바닥, 낮은 담, 접힌 형태의 잎, 배수로와 밸브. 점검 완료 상태는 서버의 정비 상태를 따른다.
- 반환실: 물이 찬 고정 보관함 두 개, 격벽, 레일과 인양 고리. 함 안은 걸어 들어갈 수 없다. D21은 이 방에서 잠긴 투명 덮개 너머 원본, 사본을 보여 주는 단말, 별도 보존 도구함을 살핀다. 도구함에는 보존 천과 도구만 있으며 원본은 구조 전까지 함에서 나오지 않는다.
- 인양 제어실: 배관, 안전 표시, 제어판. P21은 순서를 예약하며 실제 물품 구조는 R31/R32에서 일어난다.
- 중앙 로비: 벤치, 안내 기물과 통행 상태 지도. P12 경로 퍼즐을 여기에서 연다.
- 반환 접수실: 긴 접수대, 원격 연락 단말과 구조한 물품을 놓는 포장대.

주요 가구와 벽에는 짙은 녹색의 가는 외곽선을 쓴다. 작은 부품과 투명 유리는 제외하고 그룹별 선을 하나의 지오메트리로 묶어 선 때문에 호출 수가 부품 수만큼 늘어나지 않도록 한다. 문설주는 3.6 단위의 통행 공간 밖에 놓고 낮은 문턱과 가는 상인방으로 실제 출입구를 구분한다. 책상·진열장·보관함·카운터 밑에는 접지 그림자를 두고, 관장실의 시계·정비 통로의 도구 걸이·접수실의 서류 받침으로 방의 용도를 드러낸다.

## 이야기와 자원의 일치

회수 전 종이배와 원본은 반환실 함에 있다. R31/R32에서 실제 결과가 반영된 뒤에만 온전하거나 손상된 배, 온전한 원본을 포장대로 옮긴다. 밀봉 물품은 원래 함에 남으며 번진 원본을 온전하게 복원해서 표시하지 않는다. 접수실에서 밀봉 물품을 언급할 때는 인계 자료를 통해 조사하며 물품을 임의로 복제하지 않는다. E1은 반환된 배를 박물관에서 제거한다.

모로는 안내기 몸체, 함몰 화면, 작은 바퀴, 집게로 구별한다. 잠들면 화면과 안내등을 끄고 수레에 올린다. 이 상태에서는 기울임·안테나·눈 반응이 없다. 윤서는 코트·셔츠·안경·명찰을 갖추며 현재 대사에 짧은 고개와 팔 동작으로 반응한다. 나래는 S31 이후 원격 단말의 얼굴과 메시지로만 등장한다.

미래 원고, 정답, 엔딩 조건 또는 API 키를 장면에 전달하지 않는다. 조사 대상과 현재 메시지는 서버가 공개한 범위만 사용한다. 전체 박물관의 건축은 처음부터 존재하지만 해당 방에 들어갔다는 이유만으로 아직 공개되지 않은 단서를 획득하지 않는다.

## 움직임·접근성·수명

탐색 중 카메라는 플레이어를 따라가며 조사 중에는 450ms 감속 전환으로 대상에 가까이 간다. 진열장은 2.3배, 문서·단말은 2.8배, 인물과 다른 소품은 2.6배 확대하고 모바일에서는 1.65~1.9배를 사용한다. 대상의 높이를 유지하면서 화면 위쪽에 놓아 하단 대사에 가리지 않도록 한다. 메시지의 식별자가 바뀔 때만 해당 인물의 짧은 몸짓을 시작한다. 텍스트와 선택지는 움직이지 않고 음성이나 립싱크를 사용하지 않는다.

`prefers-reduced-motion`에서는 걷기와 입력 처리는 유지하며 장식 동작·눈깜빡임·입자 이동을 멈춘다. 카메라는 목표 위치를 바로 적용한다. 페이지가 숨겨지면 예약 프레임을 취소한다. 다시 보이면 제한된 시간 간격부터 재개해 누적 시간만큼 순간이동하지 않는다.

WebGL이 없거나 문맥을 잃으면 현재 상태 설명과 SVG로 전환한다. 이 경우 목적지 이동 버튼으로 동일한 도착 사건을 보내고 UI의 조사 목록으로 이야기를 계속할 수 있다.

공유 지오메트리·재료와 인스턴스를 사용한다. DPR은 최대 1.5, 렌더링은 최대 30fps다. 그림자 맵·후처리·외부 텍스처·물리·음성 의존성은 추가하지 않는다. `dispose()`는 관찰자·키보드·포인터·페이지 이벤트·프레임·인스턴스·지오메트리·재료·렌더러를 해제한다.

`diagnostics()`는 렌더 수치와 플레이어 좌표·현재 방·목적지·남은 경로 지점·근접 대상·9개 방 수를 제공한다. 이전 단일 장면의 수치를 연결 지도의 측정값으로 사용하지 않는다. 실제 보행·도착·조사와 렌더 수치는 부모 에이전트의 통합 브라우저 검증에서 확인한다.
