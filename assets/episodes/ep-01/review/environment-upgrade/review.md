# 1편 전체 3D 에셋 교체 검수

2026-10-28. 소품·배우는 `museum-low-poly-2026-10-28`, 건축·표면은 `museum-environment-2026-10-28`.

1편의 9개 방에 소품·가구 32종, 배우·단말 4종, 건축·표면 7종을 적용했다. 기본 모델 43종과 증거 변형 2개를 합쳐 갤러리는 45항목이다. 방 바닥·벽·문틀·복도·안뜰 길·물길·깔개·정비 띠·바퀴 자국까지 같은 팔레트와 실제 3D 메시 생성기를 사용한다. 문자·조사 표시·접지 그림자는 각 기능에 맞는 표현을 유지한다.

| 확인 | 결과 |
| --- | --- |
| 모델 회전 | 45항목 × yaw 8방향 × pitch 25°/43°/70° = 1,080회 WebGL 렌더 |
| 실제 방 배치 | 9개 방 × yaw 4방향 × pitch 3단계 = 108회 |
| 상태·거리·움직임 | 증거·장치 상태 4종, 대표 모델 확대 12회, 재생 중 포즈 7샘플과 reduced-motion 복원 확인 |
| 실제 플레이 | 초대장 조사, 윤서와 대화, 로비→복도→전시실 이동, UI 카메라 yaw 125°·pitch 51° 조작 통과 |
| 건축·충돌 | 출입구 폭 3.6·머리 공간 2.30, 12개 연결의 양방향 통과, 닫힌 벽·복도 난간의 충돌 확인 |
| 전체 테스트 | `npm test`: 103개 통과, 실패 0개 |
| 빌드·브라우저 | 정적 빌드 통과, 수집한 브라우저 오류 0개, 표본의 캐릭터 충돌 겹침 없음 |

정면·후면·측면·상부 contact sheet에서 45항목을 확인하고, 방·복도 회전표와 9개 방 배치, 실제 게임의 회전 전후 화면을 살폈다. 자동으로 렌더한 1,080장의 이미지를 모두 개별 육안 판정한 것은 아니다. 이전 소품·배우의 상세 검수는 [기존 기록](../review.md)에 남아 있다.

검수 중 윤서의 키에 비해 낮았던 문 상부를 올리고, 타일 모서리가 과하게 깎여 생긴 틈을 정사각 판재로 보정했다. 복도 바닥은 지도 사각형 중 방에 겹치는 부분을 빼고 실제 노출 간격인 가로 4·세로 6만 만든다. 방 위치·연결과 기존 이야기·상태 참조를 유지한다. 씬의 방 그룹 아래에 건축과 소품을 나란히 배치해 건축의 충돌 프록시가 소품 충돌을 숨기지 않도록 했다.

검수는 Headless Chromium WebGL, DPR 1에서 수행했다. 갤러리·방은 1200×900, 실제 플레이는 1440×1000이다. 관측 최대치는 갤러리 30 draw calls·4,048 렌더 삼각형, 씬 332 draw calls·44,656 렌더 삼각형이다. GPU 프레임 시간과 모바일 실제 기기 성능은 측정하지 않았다. 숫자는 이번 표본의 렌더 통계이며 성능 보증값이 아니다.

## 적용 후 배치 재감사

병렬 코드·증거·기하 감사에서 아래 배치 문제를 찾아 수정했다.

- 접수대의 트레이 3개를 상판 높이 1.385에 맞췄다.
- I02에서는 겹표제를 보이고 같은 자리에 겹치던 도장판을 숨긴다. 표제의 밑면을 책 표면에 맞추고 펼침을 유지했다. P11에서 도장판을 다시 표시한다.
- 잠금·번짐·회수 상태의 종이배와 장부를 실제 받침 높이에 맞췄다. 지지면과의 여유는 0.0005다.
- 포장대를 X축 1.55배로 넓히고 회수한 배와 장부를 분리했다. 보존 키트는 역배율을 적용해 원래 크기를 유지한다. 운반 중 손 배치는 유지했다.
- 포장대에 겹치던 로비·정비실 출구를 옮기고, 정비실 배관 2개를 벽 쪽으로 옮겼다. 보급함과 배관의 관통도 제거했다.
- 안뜰 밸브를 화단 받침과 배수구 사이의 빈 공간에 옮겼다. 조사 위치와 밸브 휠은 기존 객체를 따라간다.

이후 9개 방의 108뷰·상태·움직임과 실제 게임 진행을 다시 실행했다. 별도 8개 배치 스냅샷에서 지지 높이, I02→P11 표시 복원, 회수 증거 간격과 캐릭터 충돌 여유를 확인했다. 정적 소품의 경계 상자 교차 후보는 실제 메시·충돌 프록시로 재확인했다. 분리된 화단/배수구를 합친 경계와 회전한 단말 접지 그림자는 실제 관통이 아닌 것으로 판정했다.

수정 후 실제 씬 측정은 [배치 감사 JSON](placement-audit.json)에 남겼다. [표제 닫힘](placement-label-closed.png)·[펼침](placement-label-open.png), [P11 도장판](placement-stamps.png), [회수 배치](placement-recovered.png), [잠금 받침](placement-storage.png), [손상 상태](placement-damaged.png), [안뜰 밸브](placement-valve.png), [정비실 보급함](placement-maintenance.png)을 저장했다. manifest의 `runtimePlacement`에는 갤러리 기본 형상에 적용한 실제 씬 배율·배치 규칙을 별도로 기록했다.

이번 실제 UI 검수는 초대장→윤서→전시실과 카메라 조작을 다룬다. 모든 분기를 브라우저에서 끝까지 플레이한 결과나 모바일 실제 기기 성능 측정으로 해석하지 않는다.

## 재현

```bash
npm run build
npm test
node server.mjs 5197
```

다른 터미널에서 Playwright가 설치된 Node 패키지 폴더를 마지막 인자로 전달한다.

```bash
node scripts/check-asset-visuals.mjs http://127.0.0.1:5197 /tmp/museum-visuals /path/to/node_modules
node scripts/check-asset-gameplay.mjs http://127.0.0.1:5197 /tmp/museum-gameplay /path/to/node_modules
```

시각 검수에 `--rooms-only`를 추가하면 개별 모델 회전만 생략한다. 스크립트는 별도 브라우저 컨텍스트를 사용한다. 시작 화면·초대장·팀 선택을 거쳐 실제 게임에 진입하며 사용자의 브라우저 저장 기록은 변경하지 않는다.

2~5편의 제작 절차는 [시리즈 가이드](../../../../SERIES_ASSET_WORKFLOW.md)를 따른다. 후속편은 원고 기반 계획 상태이며 이번 1편의 완료 결과에 포함하지 않는다.
