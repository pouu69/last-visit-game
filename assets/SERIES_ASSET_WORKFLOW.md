# 5편 공통 에셋 제작 절차

매 편의 목표는 **그 편의 원고에 맞는 실제 3D 오브젝트를 제작하고, 게임에서 상태·조사·이동·카메라까지 확인하는 것**이다. 현재는 1편 박물관의 기본 모델 43종(소품·가구 32, 배우·단말 4, 환경 7)과 상태 변형 2개, 총 45항목이 구현되어 있다. 새 환경 7종까지 게임에 연결하고 [환경 확장 검수](episodes/ep-01/review/environment-upgrade/review.md)를 완료했다. 1편의 당시 검수 결과는 자동 모델 렌더 1,080뷰·방 배치 108뷰와 대표 이미지·실제 플레이 확인, 테스트 103개 통과다. 2~5편은 절차형 소품·공용 연작 배우와 게임 월드에 구현돼 있다. 후속편 43카탈로그 항목(공용 배우 중복 포함)·24방향 1,032뷰·대표 배율 36장 렌더와 전 항목 4방향 contact sheet 검토를 완료했다. 실제 1편 시작부터 같은 기록의 5편 완료와 저장 경계 검사를 통과했다. 후속편 대표 영상의 장면·모션·전환 최종 판정도 통과했다. [편별 목록](episodes/README.md)에서 원고와 진행 상태를 먼저 확인한다.

## 1. 폴더를 먼저 정한다

```text
assets/                              # 제작 관리 자료; 게임 배포 대상 아님
  README.md
  SERIES_ASSET_WORKFLOW.md            # 이 문서: 반복 제작 순서
  OBJECT_ASSET_GUIDE.md               # 3D 구현 계약
  shared/
    art-direction.md                 # 시리즈 공통 스타일·버전
    references/                      # 공통 기준 이미지와 출처
  episodes/
    README.md                        # 5편의 원고·에셋 계획·상태
    ep-01/
      README.md
      brief.md                       # 편별 공간·치수·상태·스타일 예외
      manifest.json                  # 실제 자산 목록과 원본·버전
      review/                        # 해당 편의 검수 기록·비교 이미지
    ep-02/ … ep-05/
      README.md                      # 편별 구현·검수 상태와 실행 방법
      brief.md
      manifest.json
      review/
  templates/
    episode-brief.md
    episode-manifest.json
    episode-review.md

public/assets/                       # 실제 런타임 모델과 필요한 리소스
  shared/
    core.mjs                         # 공통 기하·팔레트·재료 계약
  episodes/
    ep-01/
      props.mjs
      actors.mjs
      environment.mjs                # 방·복도·표면 환경 생성기
    ep-02/ … ep-05/
      props.mjs                      # 편별 소품 생성기
    ep-02/
      actors.mjs                     # 후속편 공용 배우 생성기
```

새 편의 모델은 `public/assets/episodes/ep-02/props.mjs`처럼 해당 편 안에 둔다. 새 배우가 있을 때만 `actors.mjs`, 실제 텍스처나 GLB를 사용할 때만 `textures/`·`models/`를 추가한다. 공통 모델로 승격할 때는 `public/assets/shared/actors/` 또는 `props/`에 둔다. 아직 만들지 않은 모델 파일이나 빈 런타임 폴더는 추가하지 않는다.

- 편 번호는 `ep-01`~`ep-05`로 고정한다. 중간 편의 방문 순서가 달라도 폴더 이름은 바꾸지 않는다.
- 팀 번호 1/2/3, 챕터 번호, 에피소드 번호는 서로 다르다. 기존 `teamId`를 에피소드 선택에 쓰지 않는다.
- 코드·리소스 이름은 소문자 영문과 하이픈을 쓴다. 한국어 이름은 manifest와 갤러리 표시 이름에 기록한다.
- 원본 코드·참고 이미지·검수 결과는 각자의 위치에 둔다. 최종 파일을 `new/`, `final2/`, `temp/` 같은 폴더에 흩어 놓지 않는다.
- 새 편을 위해 1편 manifest를 덮어쓰거나, 공통 모델의 사본을 여러 편에 복사하지 않는다.

이 구조는 현재 저장소에 적용했다. **편별 JSON은 제작 기록이며 현재 런타임의 자동 로더가 아니다.** 새 편의 생성기·갤러리·씬 연결은 아래 절차에 포함된다.

## 2. 원고에서 필요한 자산을 뽑는다

다음 편 제작을 시작할 때만 템플릿을 복사한다. 아래 `ep-02`를 대상 편으로 바꾼다. 이미 작성한 파일이 있으면 보존한 내용을 읽고 재개한다. `cp -n`은 기존 파일을 덮어쓰지 않는다.

```bash
mkdir -p assets/episodes/ep-02/review
cp -n assets/templates/episode-brief.md assets/episodes/ep-02/brief.md
cp -n assets/templates/episode-manifest.json assets/episodes/ep-02/manifest.json
cp -n assets/templates/episode-review.md assets/episodes/ep-02/review/review.md
```

브리프에 원고 경로와 실제 검토한 revision/해시, 등장 공간·인물·소품, 필수 상태, 조사 역할, 통행 폭, 공개 상태 키를 적는다. 원고에 없는 물품·해결 결과·소유 이전을 임의로 추가하지 않는다. 아직 정하지 않은 상태 키와 측정값은 비워 두고 확정하는 단계와 담당자를 적는다.

| 자산마다 기록할 것 | 목적 |
| --- | --- |
| 원고의 장면·단락 | 등장 근거와 의미 확인 |
| 공통 재사용 / 변형 / 신규 | 중복 제작 방지 |
| 일반·열림·잠김·손상 등 상태 | 필요한 메시와 애니메이션 범위 확정 |
| 누가 어디에 보관하고 언제 이동하는가 | 원본 복제와 잘못된 인계 방지 |
| 조사 지점·충돌·피벗·치수 | 실제 보행·상호작용에 연결 |
| 제작 경로·원본 ID·버전·권리 기록 | 변경 추적과 재사용 |

예를 들어 `ep-02/route-sign`은 관리용 전역 키다. 생성기의 로컬 ID `route-sign`과 구분한다. 현재 `create()`에 전역 키를 그대로 전달하면 자동으로 편을 선택하지 않는다.

## 3. 공통 스타일과 재사용 범위를 확정한다

[공통 아트 디렉션](shared/art-direction.md)을 기준으로 그 편의 재료·강조색·환경만 정한다. 대표 소품 하나와 해당 편 배경을 먼저 만들고 실제 게임 크기에서 확인한다. 팔레트·모서리·실루엣·빛·디테일 밀도가 맞으면 그 모델을 기준으로 나머지 패밀리를 제작한다.

재사용 자산은 원본 경로·생성기 ID·모델 revision·옵션을 manifest에 기록한다. 기존 승인은 원본 모델의 검수 이력이다. 새 편에 배치한 뒤의 크기·충돌·조사·등장 조건은 다시 확인한다. 모로의 몸체를 재사용하더라도 동행 여부·전원·봉인 상태는 해당 편의 원고와 공개 상태를 따른다.

공통 코어를 수정해야 한다면 영향을 받는 편을 먼저 목록에 적는다. 한 편만의 장식이나 재료 차이는 편별 생성기에서 처리한다.

## 4. 실제 3D 모델을 만든다

[구현 가이드](OBJECT_ASSET_GUIDE.md)의 `create()` 반환 계약을 사용한다.

```text
group + parts + footprint + height + pivot + collision
```

- 앞·뒤·양 측면·상부와 실제 두께를 만든다. 단일 렌더 이미지를 오브젝트로 대신하지 않는다.
- 바닥·테이블·벽 부착 기준점을 정하고 실제 bounds를 측정한다.
- 문 구멍과 빈 선체처럼 중요한 빈 공간도 모델링한다.
- 상태 변경 부품은 `parts`로 돌려주고, 변경되는 Mesh에는 `keepMesh`를 지정한다.
- 렌더용 기하와 충돌 프록시는 분리한다. 그룹 복제 뒤에는 상태 부품 참조를 다시 찾는다.
- geometry·material·texture를 등록하고 씬 수명 종료 때 해제한다. 제거한 인스턴스가 공유 자원을 해제하지 않게 한다.

소품·배우 제작과 씬 연결·검수 준비는 병렬로 진행할 수 있다. 각 작업자의 소유 파일과 공통 API를 먼저 정하고, 서로의 수정 사항을 덮어쓰지 않는다.

## 5. 해당 편의 게임과 검수 도구에 연결한다

현재 코드는 1편 박물관과 엔딩 이후 2~5편 연작을 실행한다. 후속편은 `series-game.mjs`, `series-world.mjs`, `series-action-plan.mjs`, `src/series-state.mjs`를 통해 연결한다. 새 모델 폴더나 manifest만 추가하고 연결 완료로 표시하지 않는다.

| 연결 지점 | 현재 1편 내용 | 새 편에서 연결할 내용 |
| --- | --- | --- |
| `public/asset-gallery.mjs` | 박물관 생성기·표시 이름·상태 변형 | 대상 편의 모델 카탈로그·이름·변형 |
| `public/museum-scene.mjs` | 박물관 방 배치·hotspot·공개 상태 | 해당 편의 씬 진입점·방·배치·조사 지점·상태 바인딩 |
| `public/app.mjs` 및 게임 진입점 | 현재 박물관 진행·저장 연결 | 새 편의 진입·원고·상태·저장 분리 |
| `scripts/check-asset-visuals.mjs` | 9개 박물관 방·배/장부/인양 상태 | 대상 편의 방·대표 모델·공개 상태 스냅샷·모션 |
| `scripts/check-asset-gameplay.mjs` | 초대장→윤서→전시실 | 해당 편의 실제 시작→조사→이동→핵심 상태 변화 |

후속편을 추가할 때는 편별 씬·카탈로그·검수 설정을 명시적으로 분리하거나 선택하도록 연결한다. 현재 갤러리는 `?episode=1`부터 `?episode=5`까지 선택하며 `scripts/check-asset-visuals.mjs`는 `--episode`, `--gallery-only`를 지원한다. gallery-only 결과는 방 배치·모션·실제 플레이를 승인하지 않는다. 특정 편용 검수 스크립트를 만들었다면 manifest에 실제 경로와 명령을 기록한다. 기존 박물관 검수를 통과한 결과를 새 편의 증거로 사용하지 않는다.

이야기의 판정과 아이템 지급은 게임 상태 계층이 담당한다. 모델은 공개된 상태만 표시한다. 서로 다른 편의 비슷한 물건도 같은 원본인지, 새로 만든 물건인지 구분한다.

## 6. 같은 기준으로 검수한다

실제 씬에서 소품의 밑면과 받침의 윗면을 측정한다. 잠금·손상·회수·운반 상태마다 지지 높이와 증거 사이 간격을 확인하고, 같은 작업대를 공유하는 조사 대상은 등장 상태를 전환해 가림을 검사한다. 복제·배율을 적용한 뒤 충돌 프록시와 자식 소품의 크기도 확인한다. 가구의 경계 상자가 겹치는 후보는 실제 메시와 프록시로 확인한다. 분리된 부품을 합친 경계나 접지 그림자는 거짓 양성을 만들 수 있다. 1편의 사례와 측정은 [배치 재감사](episodes/ep-01/review/environment-upgrade/review.md#적용-후-배치-재감사)에 남겼다.

| 검수 | 수행과 기록 |
| --- | --- |
| 모델 구조 | 좌표·법선·두께·피벗·UV·상태 참조·자원 해제 |
| 회전 | yaw 0/45/90/135/180/225/270/315° × pitch 25/43/70° = 항목당 24뷰 |
| 배율 | 대표 모델을 0.6/1/1.8 배율로 확인. 의도한 확대 잘림과 누락 면을 구분 |
| 방 배치 | 실제 방 수 × 4방향 × 3높이. 가림·벽 부착·접지·문 통로 확인 |
| 이야기 상태 | 등장 전·조사 중·획득/인계 후·잠금/손상 등 실제 상태별 가시성·위치 확인 |
| 움직임 | 정지 이미지와 별도로 재생 중 보행·관절·바퀴·동행 상태 확인 |
| 실제 게임 | UI로 이동·근접 조사·대화·퍼즐/상태 변화·저장 복원·카메라 조작 |
| 회귀 | 새 편의 의미 있는 검사와 영향을 받은 공통/이전 편 검사 |

이미지 개수는 실제 카탈로그 수 × 24로 계산한다. 1편 초기 소품 검수의 38항목·912뷰·9개 방이나 현재 카탈로그 45항목을 다른 편의 고정 목표·완료 숫자로 복사하지 않는다. 자동 렌더 성공과 사람이 확인한 이미지 범위를 각각 기록한다.

현재 1편 검수 명령은 다음과 같다. 먼저 빌드·검사를 실행한다.

```bash
npm run build
npm test
```

터미널 A에서 서버를 실행하고 유지한다.

```bash
npm start
```

터미널 B에서 브라우저 검수를 실행한다. Playwright를 설치한 Node 패키지 폴더를 마지막 인자로 준다.

```bash
node scripts/check-asset-visuals.mjs http://127.0.0.1:5188 assets/episodes/ep-01/review/captures /path/to/node_modules
node scripts/check-asset-gameplay.mjs http://127.0.0.1:5188 assets/episodes/ep-01/review/gameplay /path/to/node_modules
```

다른 편은 5단계에서 연결한 실제 진입점·설정을 사용한다. 브라우저 오류, 실패한 상태, 미확인 기기 성능은 결과에 그대로 남긴다. 렌더 호출 수로 GPU 프레임 시간을 추정하지 않는다.

## 7. 완료 상태와 인계물을 남긴다

| 단계 | 상태를 올리는 조건 |
| --- | --- |
| `planned-not-built` | 원고 기반 목록만 있음 |
| `modelled` | 실제 모델 소스·기하 검사·측정값이 있음 |
| `integrated` | 해당 편의 실제 씬·상태·조사·충돌에 연결됨 |
| `camera-reviewed` | 대상 모델 revision의 회전·배율·모션·방 배치를 확인함 |
| `approved-in-game` | 실제 플레이 흐름과 필요한 회귀 검사가 통과하고 근거가 저장됨 |

실패 항목이 있으면 이유·수정 대상·재개 지점을 기록한다. 승인 뒤 형상·재료·상태 연결을 바꾼 경우 영향 범위의 상태를 되돌리고 재검수한다. 모델 revision과 검수 대상 revision이 다르면 기존 승인을 승계하지 않는다.

완료한 편 폴더에는 `README.md`, `brief.md`, 실제 `manifest.json`, `review/review.md`, 측정 결과 JSON과 대표 이미지가 있어야 한다. 원본 코드·참고 이미지·검수 경로가 모두 존재하는지 확인한다. 2~5편의 계획 문서를 실제 완성 에셋처럼 표시하지 않는다.
