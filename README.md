# 폐관 후의 박물관

폐관을 앞둔 박물관에 초대된 마지막 관람객이 되어, 사라진 전시물의 행방을 추적하는 한국어 미스터리 어드벤처다. 박물관을 직접 걸으며 인물의 증언과 현장의 단서를 대조하고, 무엇을 보존할지 결정한다.

- 연결된 아홉 공간, 세 챕터, 한 경로에서 열한 번의 결정, 여섯 엔딩 계열.
- 초대장 조사와 윤서와의 만남, 첫 전시실 탐색으로 이어지는 플레이형 프롤로그.
- 작성된 NPC 대화·질문과 보존한 단서를 제시하는 추궁.
- 운송표 도장, 운반 경로, 인양 순서를 구성하는 퍼즐과 선택에 따른 결과.
- Three.js 입체 지도, 조사 대상 근접 시점, 사용자 확대·회전, 벽·가구·인물 충돌 처리.

게임 진행과 저장은 브라우저에서 처리한다. AI 호출이나 별도 게임 서버 없이 정적 웹 호스팅에 배포할 수 있다. 같은 브라우저에서 세 팀의 이야기를 따로 진행하고 결말을 비교할 수 있다.

## 빠른 실행

로컬 빌드와 미리보기에는 **Node.js 22 이상**, 플레이에는 WebGL을 지원하는 브라우저가 필요하다. API 키나 `.env` 설정은 필요하지 않다.

```sh
npm ci
npm run build
npm start
```

브라우저에서 [로컬 게임](http://127.0.0.1:5188)을 연다. 다른 포트를 사용하려면 `npm start -- 5189`로 실행한다.

`npm start`는 `dist/index.html`이 없을 때만 자동으로 빌드한다. 소스를 수정했다면 `npm run build` 후 브라우저를 새로 고친다. 자동 새로고침은 제공하지 않는다.

## 플레이 흐름

1. 타이틀 화면의 `Start Game`을 누르면 초대장이 날아온다. 봉투를 열어 내용을 읽고, `함께 입장하기`에서 팀을 고르면 첫 장면으로 전환된다. 저장 기록이 있으면 `Continue`로 바로 이어간다.
2. 현재 목표와 지도를 확인하고 목적지로 걸어가 사물과 인물을 조사한다.
3. `계속`으로 내레이션·대화·문서를 읽고, 질문과 단서 추궁으로 증언을 대조한다.
4. 선택의 대가를 확인해 A–D 행동을 확정하거나 퍼즐 조작판을 구성한다.
5. 다음 장소로 이동해 이야기를 이어가고, 엔딩에서 다른 팀의 결말과 비교한다.

새 게임은 로비 안내대의 초대장 확인 → 윤서와 인사 → 북쪽 복도 → 제1 전시실의 빈 진열장 순서로 시작한다. 다음 장면의 대사와 단서는 목적지에 도착한 뒤 공개된다. 프롤로그의 이동·조사도 자동 저장된다.

새 게임을 시작해도 이전 기록은 별도로 보관한다. 타이틀의 `다른 기록`에서 이전 이야기를 선택하거나 기록 파일을 불러올 수 있다. 초대장이나 팀 선택에서 타이틀로 돌아오면 새 기록은 만들지 않는다. 모션 감소 설정에서는 날아오기와 화면 전환 효과를 생략하고, 초대장 열기·읽기·팀 선택 단계는 유지한다.

대화·질문·퍼즐 선택 중에는 보행이 멈춘다. 현장으로 돌아가 다른 사물을 조사할 수 있으며, `대화 기록`에서 현재 장면에 읽은 메시지를 확인할 수 있다. 퍼즐은 제출 전에 수정할 수 있고, 오답도 수동 복구 경로로 이어진다. 인물의 반응과 자원·목적지 변화는 작성된 상태머신과 규칙으로 결정한다.

사물을 조사하는 동안에는 `계속`으로 대사를 읽고, 대화창의 닫기 버튼이나 `Esc`로 현장에 돌아간다. 중간에 닫은 사물을 다시 조사하면 마지막으로 표시했던 대사부터 이어진다. 마지막 대사가 표시되면 관찰 기록에 한 번 추가되며, `현장으로`를 눌러 탐색을 재개한다. 필수 관찰을 마치면 해당 NPC·작업대·장치에 표식과 상황 안내가 나타난다. 직접 다가가 `E` 또는 탭으로 상호작용하면 다음 행동의 선택·추리·퍼즐이 열린다. 우측 하단에는 수첩·대화·도움말 도구가 남는다.

수첩은 관찰 기록을 다시 보는 도구다. 첫 전시실을 조사한 뒤에는 모로와 조사 방향을 의논해 첫 조사 장소를 고른다. 이후 이송 순서 추리·기록의 차이 확인·나래의 부탁 확인도 현장 대상과의 상호작용으로 열리며, 이미 읽은 근거와 질문, 확인 뒤 할 수 있는 일을 함께 보여준다. 추리를 마치면 현장으로 돌아와 같은 대상에게 실행할 일을 정한다. 선택을 취소해도 현장의 상호작용은 유지된다. 준비 표식은 새 단서의 위치를 미리 알려주지 않는다.

### 조작

| 행동               | 조작                                     |
| ------------------ | ---------------------------------------- |
| 이동               | WASD·방향키 또는 바닥 클릭·터치          |
| 가까운 대상 조사   | E 또는 조사 버튼                         |
| 지도               | M 또는 지도 버튼                         |

| 카메라 회전·각도   | 우클릭 드래그 또는 Shift 드래그          |
| 터치 카메라 회전   | 두 손가락 좌우 이동                      |
| 카메라 설정·초기화 | `시점 조절` 패널                         |

조사 대상은 카메라가 가까이 다가가 보여준다. 평상시에는 비스듬한 시점으로 박물관을 바라본다. 벽·가구·인물·수레가 이동을 막으며, 바닥 표식·격자·안내 비콘은 통과할 수 있다.

## 저장과 기록 이동

진행은 현재 브라우저의 `localStorage`에 팀별로 저장한다. 다른 기기·브라우저·사이트 주소·포트 사이에는 자동으로 공유되지 않는다.

메뉴에서 기록을 JSON 파일로 내려받고, 다른 환경의 해당 팀에 불러오면 이어서 플레이할 수 있다. 다른 기기에서 진행한 팀 기록도 모아서 결말을 비교할 수 있다. 호환되는 이전 게임 기록도 가져올 수 있다.

저장 실패 경고가 뜨면 현재 화면에서는 메모리로 계속 진행한다. 화면을 닫기 전에 기록을 내려받아 보관한다. 브라우저 데이터를 지우거나 배포 주소를 바꾸기 전에도 기록을 내려받는다. 개인식별정보를 입력할 필요는 없다.

## 정적 배포

```sh
npm run build
```

생성된 `dist/`의 **내용 전체**를 정적 호스팅에 올린다. 배포 폴더 최상위에 `index.html`이 있어야 한다. 상대 경로를 사용하므로 `/museum/` 같은 하위 경로에도 배포할 수 있다.

산출물에는 화면, 브라우저 게임 엔진, `docs/manuscript/`의 원고, `vendor/`의 Three.js 모듈·라이선스, SHA-256을 기록한 `build-manifest.json`이 포함된다. 원고와 `vendor/`를 함께 배포해야 한다. `.env`, 로컬 저장 데이터, Node 미리보기 서버와 개발 도구는 포함하지 않는다. 빌드는 기존 `dist/`만 교체한다.

호스팅은 `.mjs`를 JavaScript로 제공하고 `.md` 원고의 텍스트 요청을 허용해야 한다. 확장자를 제한하는 호스팅에서 사용한 변환 절차는 [Dropweb 배포 기록](artifacts/dropweb-deployment.md)을 참고한다. 배포 ZIP과 메타데이터는 로컬 산출물이며 저장소에 포함하지 않는다.

배포된 게임에는 Node.js가 필요하지 않다. `npm start`의 서버는 로컬에서 정적 파일을 GET/HEAD로 제공하는 미리보기 도구다. HTML을 `file://`로 직접 여는 대신 HTTP 정적 호스팅이나 이 미리보기를 사용한다.

### Cloudflare Workers 배포

`wrangler.jsonc`는 `pouu69@gmail.com` 계정의 `last-visit`에 `dist/`만 배포하도록 설정한다. 배포 후 예상 주소는 `https://last-visit.pouu69.workers.dev`다. 별도의 Worker 코드, DB, API 키는 필요하지 않다.

```sh
npm ci
npm test
npm run deploy:check
```

`deploy:check`는 최신 소스로 빌드하고 Wrangler의 배포 설정을 검증한다. `--dry-run`이므로 파일을 업로드하거나 사이트를 공개하지 않는다. Cloudflare 환경의 로컬 미리보기는 `npm run preview:cloudflare`로 실행하고 `http://127.0.0.1:8787`을 연다.

실제 배포 시에는 로컬 CLI에서 해당 계정으로 로그인한 뒤 실행한다. Codex의 Cloudflare 연결과 Wrangler 로그인은 별개다.

```sh
npx wrangler login
npx wrangler whoami
npm run deploy
```

`deploy`도 빌드를 먼저 실행하므로 오래된 산출물을 그대로 업로드하지 않는다. 설정에 지정된 계정 ID로 배포하며, 배포 후에는 위 주소에서 시작 화면, 초대장·팀 선택, 첫 전시실 진입과 저장 복원을 확인한다. 로컬에서 저장한 기록은 배포 주소로 자동 이동하지 않으므로 필요하면 기록 파일로 내보내고 불러온다.

## 검증

```sh
npm test
```

게임 상태 전이, 단서·퍼즐·이동, 저장 복원, 충돌과 정적 빌드·미리보기 통합 시나리오를 검증한다. 빌드는 JavaScript 모듈 구문도 확인한다.

경로 명세와 실행 결과를 대조하려면 **Python 3**를 설치한 뒤 다음을 실행한다.

```sh
npm run rehearse
```

이 명령은 독립된 Python 설계 모델과 실제 선택 규칙을 비교하고, 이전 읽기판의 리허설 체크포인트를 생성한다. 루트맵·경로 검증 JSON·리허설 산출물을 다시 쓰므로 실행 후 변경 내용을 확인한다. 실제 브라우저 조작은 별도로 검토한다.

- [전체 플레이 검토](artifacts/full-play-review.md) · [충돌 검토](artifacts/collision-review.md)
- [정적 구조 전환](artifacts/static-migration.md) · [개인정보·보안 검토](artifacts/security-review.md)

`dist/`, `output/`, 브라우저 캡처, 배포 ZIP 등 생성물은 Git에서 제외한다. 테스트가 사용하는 `artifacts/narrative-check.json`과 `artifacts/full-play-complete-record.json`은 예외로 추적한다.

## 5편 연작 《돌아가는 길》

박물관 전체 3장이 1편이다. 엔딩에서 연작을 열면 모로 동행 여부를 정하고 역·극장·수리소를 방문한 뒤 강변 모임을 준비한다. 중간 세 편의 다음 방문지를 선택하며, 마지막 편의 가능한 규모는 앞서 확인한 경로·신호·장비 준비에 따라 제한된다. 준비 시간은 작업 기회 수이며 실시간 제한이 아니다.

후속편에서는 WASD·방향키 또는 바닥 클릭으로 이동하고 가까운 대상에 `E`로 조사·대화·실행한다. 내레이션과 선택 중에는 보행을 잠근다. 현장 행동을 마친 뒤 퇴장 대상에 접근해 다음 편으로 이동한다. 마우스 휠 확대와 드래그 회전은 월드에서 제공한다. 연작 화면의 기록 내려받기·불러오기로 JSON을 옮길 수 있다. 연작 저장 키는 박물관 세션별 `return-path-series-v2:<sessionId>`다.

`public/series-game.mjs`가 화면·저장·전환, `src/series-state.mjs`가 선택·준비 상태, `src/series-content.mjs`가 원고, `public/series-world.mjs`와 `public/series-action-plan.mjs`가 현장·행동·소품 투영을 맡는다. 모델 카탈로그는 `/asset-gallery.html?episode=1`부터 `?episode=5`까지 선택할 수 있다. 갤러리는 게임 진입이나 저장 경로를 대신하지 않는다.

실제 초대장부터 시작한 동일 기록으로 1편 E1·11선택을 마치고 5편의 귀환·종료까지 완료했다. 공식 저장 복원으로 박물관296이벤트와 연작39이벤트의 계보·최종 상태·모든 필수 행동을 대조했으며 브라우저 오류는 없었다. 최신 전체 검사는 136/136, 빌드는67파일이다. 전편 실행 이후의 텍스트 수정은 별도 최신 UI·집중 검사로 검증했다.

저장·새로고침·숨김 취소·캡션 재시도·준비 상태별 UI와 공간 음향 QA도 통과했다. 2~5편 갤러리43항목·24방향1,032뷰·대표 배율36장을 렌더하고 전 항목4방향 contact sheet를 검토했다. 1편 대표 영상과 양쪽 엔딩 화면을 실제 검토했으며 후속편 네 공간의 대표 영상·동작과 출발/가림/도착 전환도 최종 검토를 통과했다. 원래 요청의 구현·검증을 완료했다. 전체 모델의 개별 게임 승인을 뜻하지 않으며 manifest는 `modelled`로 유지한다. 이 결과는 로컬 검증이고 외부 배포 완료 주장은 아니다. [최종 증거](artifacts/final-evidence.md)와 [요구사항 검증](artifacts/series-requirements-audit.md)에 실행·최신 수정·한계를 구분했다.
