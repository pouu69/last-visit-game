# 폐관 후의 박물관

세 팀이 같은 밤의 서로 다른 가능성을 플레이하는 한국어 미스터리 어드벤처다. 연결된 아홉 공간을 직접 걸으며 단서를 조사하고, 장치 퍼즐과 NPC 추궁을 거쳐 열한 번의 결정으로 결말을 만든다.

**개선:** 프롤로그를 로비의 이동·초대장 조사·윤서와의 만남으로 바꾸고, 현재 목표와 다음 행동을 본편 전체에서 안내한다. 첫 경로의 발견 대사는 목적지에 도착한 뒤 공개한다.

**수정:** 초대장 확인 직후 ‘윤서와 인사하기’를 누르면 캐릭터가 멈추던 문제를 해결했다. 다른 조사 대상으로 바로 넘어갈 때도 이전 조사 카메라의 이동 잠금이 해제된다.

**변경:** AI와 게임 서버를 제거했다. 작성된 대사·질문·단서 추궁으로 진행하며, 게임 상태와 저장은 브라우저에서 처리한다. 빌드한 파일을 정적 호스팅에 올려 플레이할 수 있다.

## 배포 자료

정적 호스팅용 산출물은 `dist/`에 생성한다. [배포 기록](artifacts/dropweb-deployment.md)과 [보관용 ZIP](artifacts/dropweb-game.zip)을 참고한다.

## 실행

로컬 빌드와 미리보기에는 Node.js 22 이상을 사용한다. API 키나 `.env` 설정은 필요하지 않다.

```sh
npm ci
npm start
```

브라우저에서 http://127.0.0.1:5188 을 연다. 이 작업 환경에서 npm 기본 캐시 권한 오류가 나면 `npm ci --cache /tmp/game-playbook-npm-cache`를 사용할 수 있다.

처음 `npm start`를 실행하면 `dist/index.html`이 없을 때 자동으로 빌드한다. 소스 수정 뒤에는 다시 빌드한다. 다른 포트에서 미리보려면 다음을 사용한다.

```sh
npm run build
npm start -- 5189
```

`dist/`의 **내용 전체**를 정적 호스팅의 배포 폴더에 올린다. 최상위에 `index.html`이 있어야 한다. `/museum/` 같은 하위 경로에도 배포할 수 있다. 배포된 게임은 Node나 별도 게임 서버 없이 브라우저에서 실행된다. 미리보기 주소는 로컬 전용이다.

산출물에는 화면, 브라우저 엔진, 원고, Three.js 모듈·라이선스와 SHA-256 빌드 목록이 들어간다. `.env`, `data/sessions`, Node 서버, API 어댑터는 포함하지 않는다. 빌드는 `dist/` 안의 이전 산출물만 교체한다. 원본의 `.env`와 이전 서버 저장 파일은 건드리지 않는다. `file://`로 HTML을 직접 여는 대신 HTTP 정적 호스팅이나 `npm start`를 사용한다.

## 플레이

- `1팀/2팀/3팀 관람 시작`으로 새 게임을 만들고, `저장한 이야기 이어보기`에서 기존 기록으로 돌아간다. 이전 읽기판과 조사판 기록도 남긴다.
- 새 게임은 로비에서 시작한다. 안내대의 초대장을 확인하고 윤서를 만난 뒤 북쪽 복도를 걸어 제1 전시실로 간다. 프롤로그의 이동·조사도 자동 저장되며, 기록 이어보기는 읽던 지점에서 시작한다.
- WASD/방향키 또는 바닥 클릭·터치로 박물관을 걷는다. M/지도 버튼으로 위치와 목적지를 확인한다. 대상에 가까이 가서 E 또는 조사 버튼을 사용한다.
- 조사하면 사물을 가까이 바라본다. 휠·두 손가락으로 확대하고 우클릭/Shift 드래그·두 손가락 이동으로 구도를 바꾼다. `시점 조절` 버튼에서도 확대·회전·시선 높이를 바꾸거나 기본 시점으로 돌아갈 수 있다.
- 이야기가 다른 장소로 이어지면 그 방까지 직접 이동한다. 도착 전에는 해당 장면의 대사나 단서를 공개하지 않는다.
- `다음 메시지`로 대사를 읽는다. 현장으로 돌아가 다른 사물을 조사할 수 있다. 대화·퍼즐·질문 선택 중에는 보행이 멈춘다.
- 내레이션, 인물 대화, 단서 문서, 진행 안내, 퍼즐 힌트는 서로 다른 표시를 사용한다. `대화 기록`에는 현재 장면에서 읽은 메시지가 남는다.
- 화면의 현재 목표와 주 행동 버튼을 따라 조사→단서 대조→경로 선택으로 진행한다. 첫 사건은 진열장·모로·일정표를 차례로 확인해 무엇을 왜 찾는지 알고 선택한다. A–D 행동은 대가를 확인한 뒤 확정한다. 운송표 도장·운반 경로·인양 순서는 조작판에서 직접 구성한다. 퍼즐 제출 전에는 고칠 수 있고, 실패해도 수동 복구 경로로 이어진다.
- 모로·윤서·나래에게 장면에 맞는 준비된 질문을 고른다. 추궁에는 실제 보존한 단서를 제시하며, 작성된 규칙에 따라 대사가 이어진다.
- 서명·물건·이동은 팀이 행동을 확정할 때 바뀐다. 자유 입력이나 AI 호출은 사용하지 않는다.
- 메뉴에서 기록을 내려받고 불러올 수 있다. 같은 브라우저의 세 팀은 결말을 비교할 수 있다. 다른 기기의 팀 기록은 행사 뒤 파일로 모아 해당 팀에 불러오면 비교할 수 있다.

자동 저장은 현재 브라우저의 localStorage에 보관한다. 다른 기기·브라우저·사이트 주소에서는 자동으로 공유되지 않는다. 기록을 내려받아 옮긴 뒤 해당 팀에 불러오면 이어서 플레이할 수 있다. 저장 실패 경고가 뜬 게임은 그 화면에서 메모리로 계속 진행하므로, 기록을 내려받아 새 기록으로 가져와 보관한다. 브라우저 데이터를 지우거나 배포 주소를 바꾸기 전에는 기록을 내려받는다. 기존 서버의 저장 기록은 서버 파일로 남아 있으며, 호환되는 저장 JSON을 가져오기로 옮길 수 있다. 개인식별정보나 API 키를 입력할 필요가 없다.

## 검증

```sh
npm test
npm run build
npm run rehearse
```

마지막 명령은 기존 A–D 경로 명세와 실제 규칙을 대조하고 이전 읽기판의 리허설 체크포인트를 만든다. 지도 이동·조사·퍼즐 검증은 `npm test`의 통합 시나리오와 별도 브라우저 조작으로 확인한다. 정적 빌드·미리보기 통합 검증은 상대경로 배포, 이전 산출물 제거, 비공개 파일 제외와 GET/HEAD 제공을 확인한다.
