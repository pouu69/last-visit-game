2026-10-28 후속 요청으로 위 주소와 배포 식별자를 정리했다. 최초 감사는 읽기 전용으로 수행했으며, 이 후속 조치에서 잠금 파일과 문서·메타데이터를 수정했다. 회사 업무 문서나 실제 직원 연락처는 검사 대상에서 발견되지 않았다.

## 검사 범위

- 소스·원고·문서·테스트·빌드 설정 69개 파일.
- 배포 폴더, 현재 정적 빌드, 배포 ZIP과 이전 정적 ZIP 내부의 텍스트. 최초 검토 당시 배포 ZIP 29개 항목과 배포 폴더는 내용이 일치했다.
- 이메일, 알려진 키·JWT·PEM 형태, 인증 값, 사설 주소, 개인 경로, 한국 연락처·식별번호와 회사 메타데이터 후보.
- 이미지 50개의 메타데이터, 영상 6개의 문자열, 대표 스크린샷 2개. 전체 이미지·영상 OCR 전수 검사는 수행하지 않았다.

허구 등장인물, 이야기 속 주소, 공개 Three.js MIT 저작권 고지는 개인정보 유출로 분류하지 않았다. 과거 NPC 질문·응답과 요청 UUID는 로컬 리허설 기록에 남아 있지만 합성 게임 대화이며 배포 ZIP에는 포함되지 않는다.

실제 `.env`, `data/sessions`, 자격 증명 설정은 읽거나 수정하지 않았다. 따라서 해당 비공개 원본의 내용은 검사 결과에 포함하지 않는다. 빌드는 허용한 게임 코드·원고·라이브러리만 복사한다. 서비스 자체가 주입하는 HTML과 접근 제어는 별도의 실제 배포 확인 대상이다.

## 배포 도구 진단 응답

배포 연결 확인 중 Dropweb `doctor` 응답에 로그인 계정의 실제 이름·이메일·조직 코드가 반환되는 것을 확인했다. 원문 값은 이 보고서나 게임·ZIP에 기록하지 않았다. 프로젝트 파일 노출과는 별개인 운영 도구의 계정 정보 응답이며, 진단 결과를 공유할 때는 연결·인증 성공 여부만 추출하고 프로필 필드를 제외해야 한다. 이 대화의 도구 출력에는 원문이 표시되었으므로 해당 진단 원문을 외부에 복사하지 않는다.

## 최종 배포 확인

충돌 수정본 31개 배포 파일을 다시 확인했다. HTML 외 자산 30개는 로컬 배포본과 SHA-256이 일치하고, HTML도 서비스 삽입 부분을 제외한 원문이 보존된다. 실제 응답 HTML의 이메일 패턴 후보는 0개였으며 익명 접근은 HTTP 302, 인증 접근은 정상 응답이었다. 재생성한 ZIP에서도 이메일·키 형태·개인 절대경로 후보를 발견하지 못했다. [실제 배포 검증 결과](dropweb-collision-verification.json).
