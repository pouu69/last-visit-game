# 5편 애셋 파이프라인 실사

실사일: 2026-10-29. 문서, 실제 파일 목록, 생성기, 빌드 및 검수 스크립트를 읽었다. 이번 실사는 모델을 새로 렌더하거나 기존 승인 결과를 재검증한 작업은 아니다.

## 확인 결과

기존 파이프라인은 외부 3D 생성 API가 아니라 **공통 기하 코어를 이용한 로컬 절차적 3D 제작 → 편별 생성기 → 갤러리/게임 통합 → 카메라/플레이 검수 → manifest 기록**이다. 참고 이미지 1개는 컨셉용이며 런타임 모델은 실제 3D 메시다. 이를 유지하면 새 생성 서비스나 자격 증명이 필요하지 않다.

- `assets/SERIES_ASSET_WORKFLOW.md`: 제작 및 완료 상태 계약.
- `assets/OBJECT_ASSET_GUIDE.md`: 생성 함수, 상태 부품, 피벗, 충돌, 자원 해제 계약.
- `assets/shared/art-direction.md`: `series-art-v1` 공통 스타일.
- `public/assets/shared/core.mjs`: 실제 공통 기하/재료 코어.
- `public/assets/episodes/ep-01/{props,actors,environment}.mjs`: 유일하게 존재하는 편별 모델 생성기.
- `assets/episodes/ep-01/manifest.json`: 실제 45개 카탈로그 항목 확인. 기본 43종(소품 32, 배우/단말 4, 환경 7)과 손상 배/번진 장부 변형 2개.
- `assets/episodes/ep-02`~`ep-05`: 각각 제작 후보 README만 존재. 편별 manifest, brief, 생성기, 검수 증거가 없다.
- 기존 승인은 ep-01에만 해당하며 과거 기록의 테스트 개수/렌더 수를 현재 또는 후속편의 검증으로 인용하면 안 된다.

새 인물은 기존 윤서의 이름만 바꾼 복제본으로 만들지 않는다. 체형·복장·머리·역할 동작을 구분하되 공통 비율/팔레트를 유지한다. 나래의 기존 모델은 단말 속 초상으로 전신 모델이 아니다.

## 공통 기술 계약

```js
createEpisodeProps(core).create(localId, options)
// 반환: { group, parts, footprint: [x,z], height, pivot, collision: [] }
```

- 좌표는 Y 위, +Z 정면. 가구/인물은 바닥 중심, 소품은 받침 기준. 실제 bounds로 접지 높이를 맞춘다.
- `core.finish`는 정적 메시를 재료별로 병합한다. 변경되는 Mesh는 `userData.keepMesh = true`; 움직이는 피벗은 Group으로 유지한다.
- 충돌은 `group.userData.assetColliders`의 로컬 `{minX,maxX,minY,maxY,minZ,maxZ}` 배열. 월드 변환은 기존 `collectStaticColliders()` 계약을 활용한다.
- 부모 wrapper에 빈 명시적 충돌 배열을 넣으면 자식 충돌 탐색이 생략될 수 있다. 충돌 소유자를 분명히 한다.
- 생성기는 판정/아이템 지급을 하지 않는다. 공개 상태를 받아 시각화하는 씬이 물건의 등장·이동·인계·회수를 결정한다.
- 기하/재료/텍스처 등록 및 전체 씬 dispose를 사용한다. 인스턴스 제거 시 공유 자원을 해제하지 않는다.
- `group.clone()` 뒤 `parts`는 원본 참조이므로 재탐색해야 한다. 가능하면 factory로 새 인스턴스를 생성한다.
- 현재 `core.finish`는 revision을 `MUSEUM_ASSET_REVISION`으로 고정한다. 후속 생성기는 자기 revision 메타데이터를 명시적으로 설정하거나 호환 가능한 옵션 확장을 해야 한다. 편별 manifest revision과 실제 그룹 revision이 어긋나면 안 된다.
- 전역 관리 ID `ep-02/route-sign`과 로컬 ID `route-sign`을 구분한다. 현재 create()는 편을 자동 선택하지 않는다.

## 시각 계약

저폴리 입체 형상, 무광 큰 면, 다듬은 제조 모서리, 제한된 유리/물 투명도. 황동 metalness .28/roughness .6, 다른 불투명 재료 roughness 약 .88. 공통 팔레트는 core의 MUSEUM_PALETTE를 재사용한다. 글자는 CanvasTexture 또는 네이티브 UI; 맵이 있는 박스는 정규화 UV BoxGeometry를 사용한다.

직교 카메라 yaw 35°/pitch 43°가 기준, yaw 전체 회전·pitch 25~70° 검수. 월드 고정 광원, DPR 최대 1.5, 30fps 목표를 유지하되 새 장면의 실제 성능은 별도 측정한다. 기존 방 12×10은 강제 규격이 아니다.

## 서사상 애셋 불변 조건

1. 2/3/4편의 방문 순서 6개를 지원하므로 미방문 편의 물건/인물이 선행 등장하지 않는다.
2. 각 편 결과는 하나만 전달한다. 조사한 물건을 획득한 것으로 간주하지 않는다.
3. 모로는 동행 여부, 전원, 접속부 봉인을 따로 표시한다. 비동행이면 몸체/대사/가상 원격 등장도 없다.
4. 1편 E1의 원래 배는 강에 떠났으므로 소지품으로 복제하지 않는다. 새로 접는 배는 별도 개체다. 장부 번짐도 자동 복구하지 않는다.
5. 옛 독창은 공개 행사 음원으로 이동하지 않는다. 녹음 동의와 참석 동의는 별개다.
6. 안내등은 몸체 1개이며 고정/운반 조립 중 하나만 존재한다. 손표지/주간 운영 선택 시 전기등은 수리소에 남긴다. 점멸/회전/음향 전원 기능을 추가하지 않는다.
7. 최종편의 장비는 원고 담당자에게 회수된다. 같은 인물이 여러 장소에서 동시에 역할을 수행하지 않는다.

## 실제 통합 지점

- 새 런타임 파일은 `public/assets/episodes/ep-02/` 등 고정 편 번호 경로.
- 현재 `public/asset-gallery.mjs`는 1편 생성기와 labels를 직접 import/등록한다. 편별 카탈로그 선택을 추가해야 후속편이 검수 대상이 된다.
- 현재 `public/museum-scene.mjs`는 박물관 공간/상태를 직접 구성한다. 후속편 씬을 별도 구성하고 app에서 명시적 episodeId로 연결한다. teamId를 재활용하지 않는다.
- `scripts/build.mjs`는 public 하위를 재귀 복사하므로 새 public/assets 모듈은 자동 배포된다. 그러나 src 상대 import rewrite는 app.mjs와 museum-map 등 특정 파일에 한정되고, 원고 복사는 docs/manuscript만 대상이다. 새 씬의 import 경로와 series 원고 로딩은 빌드 후 실제 경로로 검증해야 한다.
- `scripts/check-asset-visuals.mjs`는 갤러리 카탈로그는 읽지만 확대 대상, 방 9개, 상태와 모션 검사는 박물관 고정이다. 편별 설정/진입점을 분리해야 한다.
- `scripts/check-asset-gameplay.mjs`의 초대장→윤서→전시실 검증은 새 편의 증거가 아니다.

## 권장 제작 순서 및 검증

1. 원고 해시를 기록한 편별 brief와 manifest 작성, 자산별 reuse/variant/new 및 상태 키 확정.
2. 각 편 대표 소품과 대표 공간을 기존 core로 만들고 실제 카메라 크기에서 스타일을 확인.
3. 모든 필요한 모델과 독립된 인물 제작, 상태 parts/충돌/조사 위치 연결.
4. 편별 갤러리와 씬 설정 연결, 실제 분기 상태와 소유 위치를 반영.
5. `npm run build`, `npm test`, 서버 실행 후 의미 있는 실제 UI 경로 검증.
6. 각 실제 카탈로그 항목의 8 yaw×3 pitch, 대표 모델 배율 .6/1/1.8, 실제 공간의 4방향×3높이, 공개 상태/이동/동행 모션 검사. 자동 렌더와 육안 검토 범위를 구분 기록.
7. brief/manifest/review/측정 JSON/대표 이미지가 실제 존재할 때 `modelled`→`integrated`→`camera-reviewed`→`approved-in-game` 단계로 갱신.

이번 실사에서 미확인: 현재 코드의 실제 GPU 성능, 기존 승인 후 변경된 museum-scene의 회귀, 실제 이미지 육안 상태, 사운드 청취. 이는 구현 담당의 실행 검증에 남는다.
