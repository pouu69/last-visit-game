# 충돌 처리 보완

2026-10-28. 일부 가구만 수동으로 막던 이동 판정을 실제 모델·인물·수레에 연결했다.

## 수정

- **게임플레이 수정:** 벽·기둥·진열장·책상·벤치·화단·단말기·안내판·복제 가구를 통과하지 않는다. 바닥 무늬·배수 그레이팅·빛·목표 표식과 머리 위 구조물은 길을 막지 않는다.
- 최종 위치의 일반 메시와 각 인스턴스에서 월드 좌표 충돌 상자를 수집한다. 방 전체를 상자로 만들지 않아 문 개구부를 유지한다.
- 플레이어·윤서·모로가 원형 몸체 판정을 공유한다. 키보드·클릭 경로·NPC 이동은 같은 `moveBody`를 사용하며 0.06단위 이하로 진행하고 벽을 따라 미끄러진다.
- 바닥 직사각형 합집합의 실제 외곽선으로 문 모서리 침범을 막는다. 경로의 점뿐 아니라 사이 구간도 검사한다. 움직이는 인물이 길을 막으면 다시 경로를 찾는다.
- 가구에 겹치던 윤서·모로 대기 위치, 반환실 시작점, 반환실 보급함과 접수실 단말기 배치를 보완했다.
- 잠든 모로는 수레에 실려 연속 이동한다. 수레도 가구·벽·다른 인물을 검사하고 운반 경로는 넓게 잡는다. 플레이어와 수레가 모두 목적지에 들어와야 도착한다.

## 확인

- 회귀 검사 7개: 빠른 벽 통과, 대각선 문 모서리, 가구·미끄러짐, 인물·자기 제외, 12개 문 양방향과 접선, 복제·인스턴스 월드 변환, 바닥·공중·숨김·비차단 계층 제외.
- 전체 `npm test`: 74/74 통과. 정적 미리보기 포트 검사는 로컬 포트 권한을 허용한 실행에서 통과했다.
- 실제 Chrome: 9개 방의 인물·플레이어 배치에서 겹침 없음, 키보드 벤치·전시줄 차단, 바닥 그레이팅 이동, 클릭 복도 이동, 수레 운반과 두 몸체 도착 판정. [측정 기록](collision-browser-check.json), `output/playwright/collision-check.png`.
- 실제 게임 시작 화면에서 초대장 확인 후 ‘윤서와 인사하기’가 읽기 단계로 열림을 확인했다.
- 변경 JS의 ESLint 경고 0, Prettier 확인, 정적 빌드 구문 검사 통과.

기하학·충돌 검사는 결정론적으로 수행했다. 별도 Chrome 장면 검증에서는 임시 상태 입력과 실제 키보드·마우스 및 가상 시계를 사용했다. 시작 인사 검증은 실제 게임 UI와 브라우저 저장으로 진행했다. 이번에 전체 이야기의 모든 경로를 브라우저로 다시 완주하지 않았다.

평면 이동용 원·월드 상자 충돌이며 중력·강체 시뮬레이션은 추가하지 않았다. 회전한 가구에서는 보수적인 월드 상자만큼 여유를 둔다. 저장 형식·이야기·퍼즐 규칙과 정적 배포 구조는 유지한다.
