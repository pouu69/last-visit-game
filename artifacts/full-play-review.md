# 실제 전체 플레이 검토

2026-10-28. 프롤로그부터 11번의 결정을 거쳐 E1까지 직접 진행했고, 구조 직전 저장에서 모로가 잠드는 분기를 다시 플레이해 E5까지 확인했다. 대사·내레이션·장소·이동에서 발견한 오류를 수정했다.

## 실제로 읽고 조작한 범위

대표 경로:

`O00 → S01.A → I01.B → P12.B → S12.A → T21.D → D22.A → S22.B → P21.B → R31.D → S31.A → F31.A → E1`

초대장과 윤서의 안내, 빈 진열장, 젖은 접수표, 시설 운반로 퍼즐, 모로의 실행 기록, 배수선 점검, 나래의 원래 약속과 윤서의 인정, 인양 순서, 외부 전력 구조, 수령 확인과 발송, 다음 날의 결말을 모두 읽었다. 공개된 메시지 258개에는 실제 NPC 질문·응답 한 쌍이 포함된다. 9개 방을 잇는 이동은 캔버스 바닥을 클릭해 걸었고, 서버의 도착 이벤트를 직접 호출하지 않았다.

보조 경로는 같은 플레이의 실제 내려받기 기록에서 복원했다:

`R31.C → S31.C → F33.A → E5`

모로가 전력을 내주고 잠든 뒤 수레 운반, 현재 위치에서 재조사, 작업실 인계, 배·원본 상태가 유지되는 결말을 확인했다. 이전 원고의 다른 선택 장면은 병렬 읽기 감사와 기존 경로 통합 검사로 확인했으며, 모든 분기를 브라우저로 완주했다는 뜻은 아니다.

## 발견하고 수정한 문제

### PLAY-1

**이전 방으로 되돌아가는 NPC 조사.** I01에서 P12 로비로 도착한 뒤 ‘모로에게 길 안내 묻기’를 누르면 모로의 이전 정비 통로 좌표로 플레이어가 돌아갔다. 조사 예약 자체가 모로의 보행을 멈추기도 했다. 이야기 위치는 로비인데 실제 플레이어는 정비 통로 문턱에 남아 다음 이동도 막혔다.

NPC 조사는 현재 방의 고정 합류점을 향하고, 배우와 플레이어가 같은 방·1.98m 안에 도착해야 승인한다. 목적지의 조사 대상이 아직 공개되지 않은 이동 단계에서도 동행 배우는 목적지로 걷는다. I02·I03·P11의 모로 출연 누락도 같은 출연 판정에서 수정했다. 기존 브라우저 드라이버는 모든 NPC 조사에서 실제 방·가시성·대화 거리를 검사한다.

[수정 전 화면](browser/full-play-route-misaligned.png). 같은 I01.B → P12 조건을 다시 실제로 걸었다. 로비에서 플레이어 `(0.52,15.30)`와 모로 `(0.73,17.18)`가 만나 1.90m 안에서 대화가 열렸고, 기존 브라우저 드라이버의 방·거리 회귀 검사를 통과했다. [수정 후 원자료](full-play-moro-regression.json) · [수정 후 화면](browser/full-play-moro-regression-fixed.png). 이어서 퍼즐을 제출하고 반환실 S12까지 정상 도착했다.

### PLAY-2

**잠든 모로가 스스로 걷는 문제.** 전원이 꺼진 모로도 일반 배우 경로로 이동하고 수레가 뒤따르는 구조였다. 잠든 상태와 직접 운반 선택에서는 모로의 독립 경로를 제거했다. 이동 중에는 플레이어가 수레를 운반하고, 도착한 곳에 주차한다. 이후 조사도 주차 위치에서 열린다.

실제 운반 두 구간의 이동 중 2,636 관측 프레임에서 독립 보행·자체 경로가 없고 운반자와 거리가 1m 이내임을 검사했다. [도착 후 주차](browser/full-play-sleeping-moro-parked.png) · [운반 영상](browser/full-play-sleeping-moro-to-maintenance.webm) · [운반 프레임 비교](browser/full-play-sleeping-motion-sheet.png).

### 장소와 인물 표시

- P12·D22 결과를 이동 전의 출발 의도로, S31에서 정비 통로로 향하는 결심과 F33의 도입을 실제 장소에 맞췄다.
- S22-C는 이미 존재하는 반환실 공용 조작반에서 안뜰과 같은 배수선·보조 레일을 점검하는 행동으로 명확히 했다. 새 설비·자원·경로를 만들지 않았다.
- 나래의 초상과 화자 표시는 현재 방 단말에 표시한다. 정비 통로의 F33에서 실제 발화와 표시를 확인했다.
- 포장 테이블 5개의 충돌 범위를 실제 모형과 맞췄다. 정비 통로에서 테이블 반대편으로 걸어 224프레임 중 통과 0회를 확인했다.

### 이야기와 안내

- S31은 구조 결과 → 내일의 약속과 수령지 → 공개 범위·모로 인계 순서로 조사한다.
- ‘모든 팀이 주소를 얻는다’, ‘A/B/C/D를 고르면’, 엔딩에서 가능한 전력 분기를 나열하는 표현을 실제로 확인한 행동·상태로 바꿨다. 기존 버전 원고와 자원·엔딩 규칙은 유지했다.
- 초대장을 인물 대사 대신 문서로 표시한다.
- 같은 방에서는 ‘이야기 이어가기’, 엔딩 전에는 ‘결말 읽기’로 안내하며, 실제 이동 없는 ‘이동 완료’ 알림을 제거했다. S12 → T21, S31 → F31, F31 → E1에서 확인했다.

## 읽기 판단

사건의 인과관계는 ‘도난처럼 보이는 흔적 → 정당한 반환 요청과 장치 고장 → 소유자의 원래 약속 → 무엇을 구조하고 인계할지’로 이어진다. 선택 전 대사에서 자원 조건과 손실을 알 수 있고, 구조·발송·인계 결과를 뒤에서 혼동하지 않는다. 모로의 문자 그대로 답하는 말투와 윤서의 회피·인정, 나래의 현실적인 요청은 구별된다.

규칙을 재확인하는 대사가 일부 반복된다. 특히 구조 준비와 실제 실행을 구분하는 설명은 유지했다. 엔딩의 다음 날 장면과 건물 밖 인계는 메시지 후일담이며, 3D 배경은 마지막 조사를 마친 박물관 방을 유지한다. 강가나 퇴장 동작 전체를 별도 3D 장면으로 연출한 것은 아니다.

## 최종 검사

- 기존 통합 검사 `npm test`: 82/82 통과. 새 파일별 테스트를 늘리지 않고 기존 경로·조사·퍼즐 회귀에 수정 조건을 넣었다.
- `npm run build`: 30파일 생성, 실행 JS 구문 검사 통과.
- 변경 코드 ESLint: 미정의·미사용 변수 경고 0. Prettier 적용. 별도 TypeScript 설정은 없다.
- 실제 게임 브라우저의 런타임·콘솔 오류 0건.
- 스크린샷은 실제 플레이 기록이며 픽셀 비교용 결정론적 골든 기준으로 주장하지 않는다. 이번에는 기존 실제 입력 드라이버와 이동 프레임 검사를 확장했고 새 시각 테스트 프레임워크를 추가하지 않았다.
- 로컬 서버 http://127.0.0.1:5188 실행. 외부 배포·푸시·병합 없음.

이번 검토는 `threejs-game-director`, `threejs-qa-release`와 `references/visual-test-harness.md`를 읽고 적용했다. 병렬 담당은 원고·상태머신, 화면 안내, 3D 이동·화자·충돌로 나누고 실제 플레이와 최종 검사는 주 에이전트가 통합했다.
